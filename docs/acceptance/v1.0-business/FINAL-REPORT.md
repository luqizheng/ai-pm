## 0. 验收环境前置说明（诚实性声明）

默认部署下内置 AI-PM 不可用（回复循环默认 off + 无 LLM Provider + 模型目录无 UI），经用户授权后完成三项部署配置才具备验收条件：
1. `.env` 开启 `AI_PM_CONVERSATION_REPLY=on` / `AI_PM_DISCOVERY_ORCHESTRATOR=on` / `AI_PM_CONVERSATION_ROUTER=on`（产品文档化部署开关）
2. UI 配置 DeepSeek Provider（key 用户现场提供，仅存本地）
3. 经产品 REST API 补齐模型目录/授权/general 策略（UI 缺失该面，见 B01-04）

所有业务操作均走产品 UI 或产品自身 API；未改代码、未直改数据库、未伪造任何结果。需求确认、设计/ADR 审批、任务批确认均由「人工」身份真实执行。

## 1. 十问十答

| # | 问题 | 结论 |
|---|---|---|
| 1 | AI-PM 1.0 能否独立承担项目管理辅助工作？ | **部分能**。分析、提问、拆解、起草质量高且边界严格；但开箱不可用（3 项配置断链）且无项目记忆（B09-01），「负责人助理」只能算「会话咨询师」 |
| 2 | 不连外部工程工具，项目管理流程是否完整可用？ | **是（管理面）**。创建→需求→设计→ADR→任务→排队全程不依赖 Git/Runner/MCP（初始化清单明确非必需，执行中心如实排队不伪造）；工程执行本身见 6/7 |
| 3 | AI 能否从需求讨论推进到正式需求？ | **能**（配置后）。访谈→发现→裁决→REQ 草案（pending_confirmation）→人工确认 approved 全链路验证通过；但访谈不收敛（B08-01）与答复入口缺失（B02-01）显著降低可用性 |
| 4 | 能否从需求推进到设计和 ADR？ | **领域模型能，产品化不能**。Design/Revision/ADR/审批/就绪门禁语义全部正确；但创建全靠 API（B04-02 无 UI），chat 设计咨询会被路由误吞（B04-01） |
| 5 | 能否从设计推进到任务规划？ | **能**。需求 approved → AI 自动起草 9 任务批（含 DAG 依赖+验收标准+追溯）→ 人工批量置待执行；mark-ready 对 AI 403（E5）边界正确；AI 批次 goal/deliverables 空（B05-01）需人工返工 |
| 6 | AI 建议是否受人工审批边界约束？ | **是，且全程未见越权**。六道闸门验证：需求确认、设计/ADR 审批、任务批确认、mark-ready AI 禁用、任务分解 B5 阻断（未批准需求不生成任务）、编排器 overreach 拦截 10 次。AI 输出永不直接变更正式内容 |
| 7 | 需求变更能否追踪到设计和任务？ | **部分**。影响识别正确（BC-03 冲突/权限模型/数据模型/任务范围），REQ↔TD↔ADR 关联链可见，v1/v2 版本与血统保留；但变更主路径（访谈自动出草案）不收敛，影响分析遍历入口不可达（B08-02） |
| 8 | 项目知识能否持续积累和复用？ | **积累=是，复用=否**。需求/发现/裁决/审批/任务全留痕可审计；但 chat AI 读不到任何业务记录（B03-02/B09-01），KB 空，跨会话复用断裂 |
| 9 | 工程执行与交付审查能否闭环？ | **未验收**（环境无仓库/Runner/MCP/Codex）。缺工具时行为诚实：排队+无可用执行者分类+三态分离声明，无伪造执行 |
| 10 | 是否具备正式发布所需业务成熟度？ | **不具备**（见 §4 阻断项） |

## 4. 正式发布阻断项

1. **开箱即用性**（B01-01/04）：新部署无引导无法激活 AI——与「项目创建后内置 AI-PM 必须立即可用」基线直接冲突
2. **消息黑洞**（B03-01）：需求话题消息可被永久吞掉且无感知——核心交互可靠性
3. **设计/ADR 无 UI**（B04-02）：基线 7「设计、ADR 进入正式业务流程」对普通用户不成立
4. **AI 无项目记忆**（B09-01/B03-02）：「AI 项目负责人」的核心承诺不成立
5. **访谈不收敛 + 答复入口缺失**（B03-03/B02-01/B08-01）：需求/变更主路径可靠性不足

## 5. 建议修复顺序

1. B03-01（死信）+ B03-03/B08-01（收敛与强制评审）+ B02-01（答复入口）——需求/变更主路径可靠性
2. B09-01/B03-02（chat 注入项目记录上下文：需求/任务/ADR 摘要）——兑现 AI 项目负责人承诺
3. B01-01/04（开箱引导：未启用提示+模型目录 UI 或 Provider 启用自动落目录）
4. B04-02（设计/ADR 管理 UI）
5. B08-02（影响分析入口改造）
6. B05-01（拆解补 goal/deliverables）与各 P3

## 6. 发布建议

**不建议以当前状态发布 AI-PM v1.0。**

- 领域模型质量高（状态机、审批闸门、追溯、不可变性、诚实空态均为业界良好水准），工程执行缺位时的行为完全符合「不伪造」基线；
- 但 5 项 P1 全部落在「AI 项目负责人」这条核心价值主线上：开箱不可用、消息可被吞、设计无入口、AI 无记忆。1.0 的产品叙事（AI 驱动的项目管理）与实际可体验（需要运维介入的会话咨询）差距过大。
- **建议**：修复 §5 顺序 1–3 后重新执行本业务验收（P1 清零、P2 显著收敛），并以「内部 Alpha」名义先行试用；正式发布还需叠加开发团队的自动化测试、CI、部署与安全验收结论（本报告不覆盖）。
