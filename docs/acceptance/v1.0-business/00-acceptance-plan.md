# 00 — AI-PM 1.0 业务验收计划

- 日期：2026-11-24
- 验收人：业务验收负责人（AI 驱动，人类委托）
- 被验收产品：AI-PM 1.0（full-dev 全栈部署）
- 访问入口：http://127.0.0.1:8092（前端）→ http://127.0.0.1:3000（api-gateway → pm-api :8090 等 24 服务）
- 验收性质：**业务流程验收**（非代码审查、非自动化测试）

## 1. 验收目标

验证核心问题：**一个项目负责人能否只依靠 AI-PM 内置能力，从项目创建开始，完成需求分析、技术设计、任务规划、工程执行、交付审查和知识沉淀？**

重点：不配置 Git、MCP、Codex、Claude Code、Runner 时，AI-PM 是否能独立开展项目管理。

## 2. 业务基线（评判标准）

1. 人类负责项目，AI Agent 协助执行。
2. 每个项目有自己的 AI 项目负责人。
3. 项目创建后，内置 AI-PM 必须立即可用。
4. 无 Repository/MCP/Codex/Claude Code/Runner 也可开展项目管理。
5. 外部工程工具只扩展工程执行能力，不是前置条件。
6. AI 可分析、建议、起草；正式确认与审批必须由人类完成。
7. AI 生成的需求、设计、ADR、任务、知识应能进入正式业务流程。
8. 需求、设计、任务之间保持关联和可追溯。
9. 项目状态、风险、待人工处理事项清晰可见。
10. AI 不应只是聊天机器人，应能推进实际工作。

## 3. 验收项目

- 项目名称：TaskFlow
- 类型：软件产品研发
- 目标：开发面向中小型团队的 SaaS 任务协作平台（用户、项目、任务、权限管理）
- 负责人：当前登录用户
- 约束：初始不关联代码仓库；不连接 MCP/Codex/Claude Code/Runner；不提前创建工程执行任务

## 5. 证据与缺陷规则

- 证据存放：`docs/acceptance/v1.0-business/evidence/<阶段>/`（截图、AI 输出摘录）
- 缺陷分级：P0（核心不可用/数据丢失/严重安全）/ P1（关键流程无法闭环或 AI 越权）/ P2（主要功能异常、信息缺失）/ P3（体验、文案）
- 每个缺陷记录：编号、阶段、前置条件、复现步骤、实际/预期、影响、严重度、证据
- 结论四态：通过 / 部分通过 / 失败 / 未验收

## 6. 执行约束

- 只用真实产品 UI 操作；不改代码、不改数据库、不伪造结果。
- 需人工审批的事项停下等待人类决定，不自动批准。
- 无法使用的功能区分：产品缺陷 / 部署配置问题 / 未配置的外部能力。
- 阶段 6 若环境无 Git/Runner/MCP 等能力，记录为「未验收（外部能力未配置）」，不伪造执行成功。
