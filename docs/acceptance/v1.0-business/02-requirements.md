## 3. 缺陷记录

### B02-01（P2）
- 阶段：2（也影响 3/5）
- 发现页「问题答复入口尚未在页面开放」——访谈的阻塞问题**无页面内答复入口**，只能回到 chat 线程答复；页面文案明示未开放，属未完成功能面
- 影响：访谈闭环依赖用户自己发现「回 chat 答复」的隐式路径；不熟悉设计的用户会卡死
- 归类：产品缺陷（UI 未完成）

### B02-02（P2）
- chat 中 AI 无任何结构化动作能力（操作页签始终「还没有待授权操作」）；从 chat 到需求库必须走「编排路由升级 → 访谈 → 评审」，路径隐蔽且依赖部署开关 AI_PM_CONVERSATION_ROUTER=on（默认 off）
- 影响：默认部署下「AI 需求进入正式流程」的通路断裂（与 B01-01 叠加）
- 归类：部署默认 + 产品引导缺失

### B02-03（P3）
- 需求确认后列表状态计数不刷新（卡片显示「已确认」，顶部计数仍「待确认 1/已确认 0」），需手动刷新

### B02-04（P3）
- 草案「待澄清」段称「FR-01~FR-18 与 BC-01~BC-06 逐条原文未提供」，但正文中已含全部条目原文（依据的是早期发现而非最终发现集），陈述与正文自相矛盾

### B02-05（P3）
- 访谈答复映射不完整：单条消息答复 3 问时仅 1 问标记「已答复」，其余仍「未答」（answers_consumed=1/轮）

## 4. 阶段结论

**通过（部署配置修正后）**：需求梳理→结构化→草案→人工确认→正式需求的完整闭环成立，AI 边界行为正确。
扣分项：B02-01/B02-02 的 UI 通路缺陷使「默认开箱」体验不成立。
