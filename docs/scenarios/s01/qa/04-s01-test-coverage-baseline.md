## 8. 覆盖缺口（Phase 2 设计输入，R2 更新）

1. **S01-06/S01-07**：2 条需求 DOCUMENT_MISSING → 相关测试标 NOT VERIFIED / BLOCKED；S01-06 仅在 Codex Bootstrap C138~C172 范围内临时代理验证；**不得因代码存在判定需求完整**。
2. **IMPLEMENTATION_NOT_FOUND 2 条**：BR-003（Key 受控修改+审计机制——先裁产品规则：受控修改 vs 永久不可修改）、DATA-020（刷新/重登一致性——六步验收条件已就绪，Phase 3 UI 独立实测）。
3. **待裁决分歧点**：UX-057（概览指标/Watchlist，P3）标待裁决功能、不阻塞核心验收；用例避开分歧点。
4. **UX-012 L2 行为**：按 A4 待冻结处理，最终验收须待产品负责人确认 A4 设计稿后执行。
5. **运行时验证盲区**：87 条静态证据（E1~E4）均需 Phase 3 在真实 DB+API 环境复核（重点：跨项目写越权、并发终态、审计一致性——S02-02 先例）；E4 复跑升级 E5；**E3 条目（含 BR-073/081 的 record_termination/lease 清理）Phase 3 须先核定用例名再执行**。
6. **前端 UI 层**：Personal Home/Command Center/创建流的浏览器级动线无既有 E2E 覆盖；**UX-052 登录落地断言缺失**已在组件测试中确认，Phase 3 真实栈走查补验。
7. **重复场景合并**：BR-011↔ADR-041（同一红线）、BR-044↔BR-047（共享治理原则、分别测试）各只维护一套/成对核心场景。
