# PM-AI 全局导航 IA 基线 V1.0（裁决草案）

> 日期：2026-11-16  
> 上游依据：《PM-AI 全局导航 IA 现状审计报告 V1.0》  
> 基线状态：待产品负责人确认  
> 适用范围：PM-AI Web 前端全局导航、页面归属、导航层级、上下文切换和导航可见性

## 1. 基线目标

建立与 PM-AI 业务领域、数据归属和权限边界一致的全局信息架构，解决当前导航中领域合并、权威页面不可达、团队管理分散、命名误导、项目上下文不一致等问题。

本基线是目标 IA 设计，不是当前前端实现现状。建议方案未经产品负责人确认前，不视为正式裁决。

## 2. 核心原则

1. 按业务领域组织导航，不按当前页面组件组织导航。
2. Personal、Team、Project 三个上下文清晰分离。
3. KB、Product Cognition、Project Cognition、Analysis 四个领域必须有明确、可区分的入口。
4. 领域页面负责领域对象和生命周期；人工审核中心负责跨领域待人工处理事项。
5. 项目总控台是项目日常工作主入口；仓库、SSH、Runner 等一次性或配置型能力归入项目设置。
6. 顶栏保留 Team Switcher 和 Project Switcher，不引入 Workspace Switcher。
7. 菜单可见性是 UX 控制，不是后端授权的替代品。
8. 项目上下文必须在导航、页面数据、面包屑和 AI 上下文中保持一致。

## 4. 领域职责

| 领域 | 主要职责 |
|---|---|
| Personal | 个人主页、通知、个人设置 |
| Team | 团队总览、项目列表、成员邀请、团队设置 |
| Project Command Center | 项目状态、待人工处理、当前执行、风险、初始化进度 |
| Analysis | Analysis Run、Report、Finding、分析结论及报告生命周期 |
| KB | Source、Document、Revision、Memory、Proposal、Knowledge Review |
| Product Cognition | 产品定位、目标、业务领域、能力、模块、角色、场景、流程、业务对象和业务规则 |
| Project Cognition | 项目技术认知、项目知识、认知分析、人工确认与决策历史 |
| 人工审核中心 | 汇总跨领域待人工处理事项，不接管各领域自身的确认语义 |
| 项目设置 | 仓库、SSH、Runner、AI 配置及项目级执行策略 |

V1 暂按项目上下文呈现 KB / PC 等入口，不在导航中引入 Team 级知识库。

## 6. 全局框架

### 顶栏
- 产品标识。
- Team Switcher。
- Project Switcher。
- 全局搜索/命令面板。
- 通知入口。
- AI 助手入口。
- 账户菜单。
- 不设置 Workspace Switcher。

### 左侧导航
- Personal、Team、Current Project、Platform Administration 分区。
- 分组支持折叠。
- 当前项目和当前页面状态明确。
- 项目未选中时，项目模块提供清晰引导。
- 详情、历史、ADR、Run 等下钻页面不全部放入一级导航。

### 内容区
- 项目总控台是项目工作主入口。
- 各领域使用独立页面和清晰标题。
- 页内 Tab 只组织本领域子视图，不跨领域合并。
- 面包屑表达 Personal / Team / Project 归属。

### 右侧 Context Panel
- 作为 AI 协作辅助区域，不替代主导航。
- 保留 Context、Sources、Results、Actions、History 五类上下文视图。
- 根据当前领域显示相关信息，但不能把正式领域页面隐藏在右栏中。

## 7. 权限与上下文

1. 管理入口按授权角色显示；具体角色映射由权限模型确定。
2. 团队成员和邀请入口归入团队设置。
3. 项目模块按当前项目成员关系和权限状态决定可见性。
4. 前端菜单隐藏不替代后端 API 授权。
5. 直接访问路由和 API 必须执行服务端身份、租户、项目成员和领域权限校验。
6. 当前项目上下文建议统一由 `shell.currentProjectId` 管理；URL 参数用于初始注入和深链。
7. 项目切换后，菜单、页面数据、面包屑和 AI 上下文必须保持一致。

## 9. 实施阶段

- Phase 1：导航纠偏。修正名称、删除占位入口、归并团队设置、增加项目总控台和项目认知入口。
- Phase 2：领域入口拆分。KB、PC、Analysis 建立独立导航目的地。
- Phase 3：领域管理面建设。补齐 PC 对象/提案/冲突、KB Source/Memory/Proposal、Analysis Run/Report 管理。
- Phase 4：上下文和权限收敛。统一项目上下文，完成路由与 API 授权验证。

## 10. 验收标准

1. 四域入口清晰，领域权威边界不会被 UI 合并。
2. Project Cognition 和项目基线有明确可达入口。
3. 团队成员、邀请、团队 AI 配置统一归入团队设置。
4. 团队总览与项目总控台语义清楚。
5. 项目切换后菜单、页面数据、面包屑和 AI 上下文一致。
6. 未授权用户不能通过直接 URL 或 API 绕过权限。
7. 占位、规划中能力明确标识，不伪装为已实现能力。
