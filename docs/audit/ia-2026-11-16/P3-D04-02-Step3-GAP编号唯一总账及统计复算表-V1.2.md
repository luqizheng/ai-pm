## 五、T4 GAP-07 实施承载映射（V1.2 重区分：发布段严格指纹幂等=未实现，GAP-27 承载）

**勘误原则**：completed 短路重放机制的存在，不得被用于证明「同 op+同完整 fingerprint 返回原 receipt」与「同 op+异 fingerprint 拒绝 409」两条严格指纹幂等条件已满足——短路分支（publish.rs:147-163）不比对任何指纹。

| Q-04 幂等要求 | 承载 GAP | 承载方式 | 现状〔V1.2 逐行重区分〕 |
|---|---|---|---|
| 同 op 重放→原 receipt（起草段） | **GAP-01** | 账本行+指纹列 | 未实现→GAP-01/27 实施批 |
| 同 op 重放→原 receipt（发布段，**短路机制**） | GAP-15（机制登记）/GAP-31（键） | completed 短路 | **CODE FACT 已满足**（publish.rs:110-179；TEST FACT pc_model.rs:1096-1116：replayed=true 且版本数=1） |
| 同 op+**同完整 fingerprint**→原 receipt（发布段，**严格判定**） | **GAP-27** | 账本指纹列+命中时比对确认 | **未实现**：短路返回不比对指纹；账本无指纹列（expected_content_hash 仅 INSERT 占位串 `'pending'`，publish.rs:114，全流程无 UPDATE/比对）→GAP-27 实施批 |
| 同 op+**异 fingerprint**→409（发布段+起草段） | **GAP-27** | 账本指纹列+失配拒绝 | **未实现**：completed 短路无条件返回原 receipt（:147-163 无任何比对）；pending/failed 重放走提案锚三方比对+CAS（:181-227/:264-317）=另一机制，非账本指纹比对→GAP-27 实施批。结构性缓解（键派生自 proposal_id+提交后内容锚不可变）≠显式比对，不据此标已满足 |
| 异 op+同 content → 并存 | 无需承载 | 无内容唯一约束 | **SCHEMA FACT 已满足**（proposal_content_hash 无 UNIQUE，0001:3240-3264）；发布段并存专门用例缺位（登记，随 GAP-29/30 配套批，不新增编号） |
| 内容/基线变化 → 新逻辑身份 | 设计规则 | CAS 失配→failed→re-propose | **CODE FACT 已满足**（publish.rs:264-317） |

**结论（V1.2 修订）**：GAP-07=语义闭合历史记录；实施承载**无独立条目**——起草段账本=GAP-01、**严格指纹判定（两段，含发布段）=GAP-27**、发布键=GAP-31、短路机制=GAP-15（范围限定）+既有 CODE FACT。**不重复计入实施差距、不新增编号。**
