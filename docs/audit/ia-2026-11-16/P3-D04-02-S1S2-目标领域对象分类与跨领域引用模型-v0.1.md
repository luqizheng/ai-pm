## 1.1 五形态通用模型与各域形态配置

五形态关系（通用）：


## 1.3 五形态间的形成路径与转移规则（通用）

两条形成路径，终点都是「正式」：

```
路径 A（AI 提案）：AI 分析/提取 ──▶ Proposal（附证据与来源钉扎）──▶ 人工 Decision
路径 B（人工直接）：授权人工起草 Revision ──▶ L1 自确认 或 L2 审批（=Decision）
路径 A/B 汇合 ──▶ 正式化（认知域=Publication 成员；KB=confirm/review 翻转；交付设计域=current 指针推进）
```

通用不变量（对全部域生效）：
1. 身份不含正文；改正文必产生新 Revision（G-06）；
2. Decision 不可变、不可事后替换；
3. AI 的一切产物止步于 Proposal/候选层，正式化必经人工（指令 §四-8/9）；
4. 引用创建时钉扎目标 Revision（依据类引用）；
5. 正式化后历史不可覆盖，替代走显式状态（superseded/deprecated），不删除。

# Part 2（Step 2）：跨领域引用模型（O-02 / O-09）

## 2.1 DomainRef 契约（四字段【冻结 R-07】）

| 字段 | 语义 | 约束 |
|---|---|---|
| `target_domain` | 被引用对象所属业务域 | 域注册表（含 project_cognition；product_plan 永久排除【冻结】） |
| `target_object_type` | 被引用对象类型 | **必须在目标域的类型注册表内**（闭合 V1.1 G5 缺口——注册表设计归 S4/O-03） |
| `target_object_id` / `target_object_key` | 被引用对象的稳定身份 | 指向对象身份，不指向 Revision |
| `revision_context` | 版本上下文（抽象） | 见 §2.2 解析模式 |

职责分离【冻结】：DomainRef 描述被引用对象；`*_relationship_type.owner_domain` 描述关系确认权威。禁止合并。

## 2.2 版本语义：两种解析模式【提议 2】

| 模式 | revision_context 取值 | 适用 | 自动改写 |
|---|---|---|---|
| **R1 钉扎（Pinned）** | 具体 Revision 标识 | **依据/证据类引用（默认且强制）**：认知依据、需求依据、评审依据 | 永不。目标出新版只产生 DRIFTED 待办（G-03） |
| **R2 最新（Latest-published）** | 空 + intent=latest | 仅限**展示/聚合/统计**场景（地图连线、计数、摘要） | 读取时解析最新已发布版本；结果必须携带版本元数据【冻结 R-08】 |

不变量：正式认知对 Requirement/Design/ADR/KB 的依据引用必须 R1（Q-PC-03、PC 基线 §7.4 的域内规则升为全域规则）。R2 引用不得作为任何确认/发布的事务依据。

## 2.3 引用生命周期状态（读取时由 Resolver 判定【提议 3】）

| 状态 | 判定条件 | 系统行为 |
|---|---|---|
| VALID | 目标可达+权限通过+钉扎版本仍有效 | 正常返回 |
| DRIFTED | 目标存在新 Revision（R1 引用未跟新） | 返回内容+漂移元数据；由**引用域**产生待人工处理事项（G-03 影响识别），不自动改写 |
| TARGET_SUPERSEDED | 目标对象被 superseded_by 替代 | 返回替代链；重定向=引用域显式变更提案（人工确认），不自动（G-04） |
| TARGET_DEPRECATED | 目标废弃但仍可达 | 返回内容+废弃标记；引用保留 |
| UNREACHABLE | 目标删除/不存在 | evidence 类：降级为历史锚永久保留（审计）；association 类：标记失效待人工处理 |
| DENIED | 权限闭环三条件任一不满足 | **不返回内容**，仅返回状态与元数据（红线二） |

实现口径：状态是 Resolver 在读取时推导的**视图**，不要求引用行持有可变状态列（是否物化 last-resolve 状态属 P3-10 实现细节）。

## 2.4 替代与重定向语义【提议 4】

1. 目标对象替代（superseded_by）：旧引用不失效、不自动重定向；Resolver 返回完整替代链。
2. 重定向 = 引用域内的一次显式变更（走引用域自己的提案/确认流程，人工决策留痕）。
3. 删除目标对象：认知域/KB 禁删（触发器【冻结现状】）；Git 知识空间文档可删——删除前其被引用关系由引用域收到 UNREACHABLE 待办；不做级联删除、不做自动改写。
4. 引用域对象自身的废弃/替代，不影响它持有的对外引用记录（历史锚保留）。

## 2.5 权限变化语义【冻结红线二 + 权限闭环】

- 引用关系本身不构成任何授权凭证。
- 跨域操作（读内容/确认/撤回/发布/遍历/统一检索摘要与衍生内容）须同时满足：调用方授权 + 目标领域授权 + 目标对象当前状态约束（L3 冻结期拒绝变更类操作）。
- 权限回收后：引用保留（身份锚），内容解析返回 DENIED 元数据；统一检索按权限过滤【冻结 R-08】；不因权限变化删除或改写引用。

## 2.6 Resolver 契约（供 P3-10 / O-01）

```
resolve(ref: DomainRef, ctx: { caller, tenant, project, intent: READ|NAVIGATE|ITERATE })
→ { status: VALID | DRIFTED | TARGET_SUPERSEDED | TARGET_DEPRECATED | UNREACHABLE | DENIED,
    target:  { domain, object_type, object_id, revision_id?, version_label? } | null,
    permission: { caller_ok, domain_ok, state_ok },
    drift: { latest_revision_id?, superseded_by? } | null,
    error:  NOT_FOUND | REV_MISSING | DEPRECATED | SUPERSEDED | DENIED | DOMAIN_NOT_OPEN }
```

- 每域实现**本域 resolver**；引用方禁止跨 schema 直查【冻结】。
- 遍历边界：0007 双端隔离规则跨 schema 继续生效【冻结】。
- intent=ITERATE（统一检索聚合）时结果必须携带原始领域/身份/版本/权限判断元数据【冻结 R-08】。

## 2.7 校验分层（O-03 联动预告，S4 展开）

| 层 | 负责什么 |
|---|---|
| 契约层（写入时） | domain 在注册表 + type 在目标域类型注册表 + revision_context 形态合法 |
| 各域 DB 层 | 仅本域对象/修订完整性（触发器/约束）；**跨域一律无 FK**（跨 schema 引用只走契约） |
| Resolver 层（读取时） | 存在性、版本、权限、状态 |
