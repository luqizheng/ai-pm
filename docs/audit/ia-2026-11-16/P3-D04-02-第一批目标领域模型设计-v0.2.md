# Part 1（Step 1）：目标领域对象分类

## 1.1 五形态通用模型与各域形态配置（R1 修正）

五形态关系：

```
对象身份 Object（稳定，不含正文）
   └── 内容版本 Revision（对象内容的一次版本，正式化后不可变）
   提案 Proposal（变更意图 + 变更集合；指向对象/Revision，不是 Revision 本身）
        ──▶ 人工决策 Decision（针对该提案或确认对象的不可变事实，append-only）
             ──▶ 正式发布版本 Publication（适用域对已确认内容的不可变快照）
```

**形态概念与域内载体分离（R1 核心）**：五个形态是概念层；每个域选择自己的**载体**实现概念。「载体复用 ≠ 形态合并」——一个物理对象可同时承载两个形态的角色，但概念上仍是两个形态、两条语义。

各域形态配置（●=独立载体；◐=由其他形态的载体兼任【载体复用】；—=该域不设此形态）：

| 形态 | PC | ProjC | KB | Delivery | Design | Plan |
|---|---|---|---|---|---|---|
| 对象身份 | ● | ● | ●（Source/Document/Memory） | ● | ● | ● |
| 内容版本 | ● | ● | ● | ● | ● | ● |
| 提案 | ●（独立 proposal 对象，成员指向被提议 Revision） | ●（同构） | ◐ Memory：变更意图由 **PENDING_REVIEW 审核流程承载**（台账 §2.4 冻结：双轨保留、不合并为统一实体——此为载体复用，概念上提案≠Revision）；◐ Document：无提案形态，draft Revision 即候选，确认门直达 | ◐（修订起草即候选） | ◐（同左） | ◐（同左） |
| 人工决策 | ●（approval，多行追加） | ● | ◐（confirm/review 事务内产生决策记录+审计+状态翻转；不设独立 approval 对象） | ●（requirement_confirmation） | ●（design_approval） | ●（计划批准） |
| 正式发布版本 | ●（cognition_version+member） | ● | —（无快照形态）【提议 P1】 | —（current_revision 指针） | ◐（implementation_baseline=冻结基线快照） | —（物化为 delivery.task 即生效） |

> 设计说明：cognition 两域五形态齐全（P3-11 已验证机制）；KB/Delivery/Design 不强加 Publication——只有需要「一组对象整体快照语义」的域才设该形态。

## 1.3 五形态间的形成路径与不变量（R2/R3 修正）

两条形成路径，终点都是「正式」：

```
路径 A（AI 提案）：AI 分析/提取 ──▶ Proposal（附证据与来源钉扎）──▶ 人工 Decision
路径 B（人工直接）：授权人工起草 Revision ──▶ L1 自确认 或 L2 审批（=Decision）
路径 A/B 汇合 ──▶ 正式化（认知域=Publication 成员；KB=confirm/review 翻转；交付设计域=current 指针推进）
```

通用不变量：
1. 身份不含正文；改正文必产生新 Revision（G-06）；
2. **Decision 是不可变的历史事实（append-only）**：不可变指历史决策记录本身；同一对象再次发生决策时产生**新决策记录**，不得覆盖、改写或替代历史记录；当前有效决策由记录序列推导（R3）；
3. **AI 能力三级（R2）**：
   - AI **可以**创建领域允许自动登记的基础资产（如 KB Source 登记、来源/证据登记）；
   - AI **可以**创建候选内容与提案（draft/proposal，止于待确认层）；
   - AI **不得**绕过人工确认门完成需要人工确认的正式认知采纳、审批与发布；
   - 本条只做能力分层表述，**不改变 KB/PC/ProjC 已冻结的人工确认边界**（各域门清单以冻结裁决为准）；
4. 引用创建时按引用类别钉扎目标 Revision（§2.2/§2.3）；
5. 正式化后历史不可覆盖，替代走显式状态（superseded/deprecated），不删除。

# Part 2（Step 2）：跨领域引用模型（O-02 / O-09）

## 2.1 DomainRef 契约（四字段【冻结，不扩展第五字段】）

| 字段 | 语义 | 约束 |
|---|---|---|
| `target_domain` | 被引用对象所属业务域 | 域注册表（project_plan 永久排除【冻结】） |
| `target_object_type` | 被引用对象类型 | 必须在目标域类型注册表内（注册表设计归 S4/O-03） |
| `target_object_id` / `target_object_key` | 被引用对象稳定身份 | 指向对象身份，不指向 Revision |
| `revision_context` | **引用契约的版本选择语义**（显式模式声明，见 §2.2） | 无模式声明=非法契约 |

职责分离【冻结】：DomainRef 描述被引用对象；`*_relationship_type.owner_domain` 描述关系确认权威。

**引用类别不进 DomainRef（R6）**：evidence/basis/association/display/aggregation 等引用类别由**引用关系定义**（如 relationship_type 的定义所载）或**所属领域引用契约**提供，不由 DomainRef 字段表达——四字段契约不变。

## 2.2 版本语义：两维正交（R4 修正）

**维度一：Reference Version Mode（版本选择模式，属于引用本身，经 revision_context 显式声明）**

| 模式 | revision_context 表达 | 约束 |
|---|---|---|
| **Pinned（钉扎）** | `{mode: pinned, revision: <明确 Revision 标识>}` | 必须携带明确 Revision 标识 |
| **LatestPublished（最新已发布）** | `{mode: latest_published}` | **必须显式声明**；revision_context 为空/缺 mode = 非法契约，**不得隐式推断** |

- LatestPublished **只允许用于非正式依据**的展示、聚合和统计场景；**不得成为确认、审批、发布或正式认知的依据**。
- 依据类引用（evidence/basis）强制 Pinned。

**维度二：Resolver Operation Intent（解析操作意图，属于一次 resolve 调用，经 ctx.intent 传入）**

| intent | 用途 | 影响 |
|---|---|---|
| READ | 读取目标内容/详情 | 权限判定+返回内容（按目标域策略） |
| NAVIGATE | 导航/跳转 | 权限判定+返回定位信息 |
| ITERATE | 统一检索聚合遍历 | 权限过滤+强制携带领域/身份/版本元数据【冻结 R-08】 |

两维正交：intent 不改变版本选择；mode 不改变权限判定。组合矩阵（如 Pinned+ITERATE、LatestPublished+READ）均合法，行为由本节规则叠加决定。

## 2.3 引用类别与不可达处理（R6 新增）

类别登记位置：由**引用关系定义**或**所属领域引用契约**提供（登记的具体载体形式归 schema/API 设计阶段）。

| 类别 | 语义 | 版本模式约束 | 目标 UNREACHABLE 时处理 | 人工待办 |
|---|---|---|---|---|
| **evidence 证据** | 支持认知的历史事实锚 | 强制 Pinned | 降级为**历史锚永久保留**（引用记录+失效原因留痕）；不重定向 | 无（审计留痕） |
| **basis 依据** | 正式确认/审批所依赖的目标 | 强制 Pinned | 引用域产生待人工处理；目标恢复或显式重定向前，依赖它的业务动作按各域规则阻断或警示 | **是** |
| **association 关联** | 对象间业务关联 | Pinned | 失效标记；重定向须引用域显式变更 | 由引用域决定 |
| **display 展示** | UI 展示/导航 | 两者皆可 | 自动降级（隐藏/占位/回退最新可用） | 无 |
| **aggregation 聚合统计** | 计数/汇总 | 通常 LatestPublished | 从统计中排除并计数留痕 | 无 |

**历史锚保留 ≠ 目标内容可访问性**：永久保留的是引用记录及其失效原因；目标内容的访问始终受目标域权限与目标存续约束（可能 DENIED 或不存在）。

## 2.4 引用生命周期状态（R7/R8 修正）

状态由 Resolver 读取时推导（是否物化 last-resolve 状态属 P3-10 实现细节）：

| 状态 | 判定 | 语义（V0.2 精确化） |
|---|---|---|
| VALID | 可达+授权+版本一致 | 正常 |
| DRIFTED | 目标有新 Revision（Pinned 未跟新） | **版本差异提示，不等于引用失效**：引用仍有效、内容仍返回；产生漂移元数据 |
| TARGET_SUPERSEDED | 目标对象被替代 | **保留原目标，不自动重定向**：内容可返回+替代链元数据 |
| TARGET_DEPRECATED | 目标废弃但仍可达 | 返回内容+废弃标记；**不代表允许所有新引用与所有业务操作**——新引用是否允许、哪些操作受限由目标域策略与 L3 冻结规则决定 |
| UNREACHABLE | 删除/不存在 | **区分两件事**：历史锚保留（引用记录+原因，按 §2.3 类别处理）≠ 目标内容可访问（不可访问） |
| DENIED | 权限闭环任一不满足 | **最小信息返回**（见下） |

**DENIED 信息泄漏边界（R7）**：只返回调用方**有权获知的最小必要信息**；不得默认暴露目标对象的存在性、类型、版本、废弃状态或替代关系。某调用方对「对象存在性」是否可见，由**目标领域安全策略**决定（存在性可见时方可返回存在级元数据）。

**status 与 error 的职责（R8）**：status=业务解析结果；error=仅在目标**不可解析或不可授权**时的技术原因。同一结果不得同时被表达为互相矛盾的业务状态与技术错误。

| status | error | 性质 |
|---|---|---|
| VALID | — | 成功 |
| DRIFTED | — | 成功 + 漂移元数据 |
| TARGET_SUPERSEDED | — | 成功 + 替代链元数据 |
| TARGET_DEPRECATED | — | 成功 + 废弃标记 |
| UNREACHABLE | NOT_FOUND / REV_MISSING | 技术不可达 |
| DENIED | DENIED | 不可授权 |
| （契约层拒绝） | DOMAIN_NOT_OPEN / INVALID_CONTRACT | 目标域未开放 / 契约非法（无模式声明等） |

（V0.1 error 枚举中的 SUPERSEDED/DEPRECATED 移除——它们是带标记的成功状态，不是错误。）

待办产生：**由引用域决定**是否产生人工待办及后续处理（默认规则见 §2.3 类别表；引用域可按自身治理收紧，不得放松 evidence/basis 的下限）。

## 2.5 替代与重定向语义（V0.1 维持 + R8/R9 强化）

1. 目标对象替代：旧引用不失效、不自动重定向；Resolver 返回完整替代链；
2. 重定向=引用域内显式变更（走引用域自身提案/确认流程，人工决策留痕）；
3. 删除目标：认知域/KB 禁删【冻结现状】；Git 知识空间文档可删——被引用关系由引用域按 §2.3 收 UNREACHABLE 处理；无级联删除、无自动改写；
4. 引用域对象自身的废弃/替代不影响其持有的对外引用记录（历史锚保留）。

## 2.6 权限语义（冻结红线二 + 权限闭环 + R7）

- 引用关系本身不构成任何授权凭证。
- 跨域操作须同时满足：调用方授权 + 目标领域授权 + 目标对象当前状态约束。
- 权限回收后：引用保留（身份锚）；解析返回 DENIED（最小信息）；统一检索按权限过滤【冻结 R-08】；不因权限变化删除或改写引用。

## 2.7 Resolver 契约（供 P3-10 / O-01；R4/R7/R8 修订）

```
输入：
  ref: DomainRef（revision_context 含显式 mode：pinned{revision} | latest_published）
  ctx: { caller, tenant, project, intent: READ | NAVIGATE | ITERATE }

输出：
  status: VALID | DRIFTED | TARGET_SUPERSEDED | TARGET_DEPRECATED | UNREACHABLE | DENIED
  error:  NOT_FOUND | REV_MISSING | DENIED | DOMAIN_NOT_OPEN | INVALID_CONTRACT   // 仅失败态非空
  target: { domain, object_type, object_id, revision_id?, version_label? } | null  // DENIED 时按最小信息边界，默认 null
  permission: { caller_ok, domain_ok, state_ok }        // 仅在存在性可见策略允许时返回
  drift: { latest_revision_id?, superseded_by?, deprecated_at? } | null            // 元数据按调用方可获知范围裁剪
```

- 每域实现**本域 resolver**；引用方禁止跨 schema 直查【冻结】。
- 遍历边界：0007 双端隔离跨 schema 生效【冻结】。
- ITERATE 结果必须携带原始领域/身份/版本/权限判断元数据【冻结 R-08】，且元数据本身受 R7 最小信息边界约束。
- 存在性可见策略（existence_visible）属目标域安全策略，P3-D05 治理规范承接细化。

## 2.8 校验分层（V0.1 维持，S4 展开）

契约层（domain 注册表 + type 在目标域注册表 + revision_context 模式合法）；各域 DB 层（仅本域完整性，跨域一律无 FK）；Resolver 层（存在性/版本/权限/状态读取时验证）。

## 2.9 Reference Stability Principle（引用稳定性原则，R9 新增【新增原则，随本批待审】）

> 正式引用一旦被确认或随正式对象发布，其目标身份与版本语义必须保持稳定。目标对象后续发生版本更新、替代、废弃、权限变化或删除，不得静默改变原引用的含义。任何重定向、版本替换或引用关系修改，必须由引用所属领域发起新的显式变更，并经过该领域规定的确认机制。LatestPublished 仅适用于非正式依据场景。

推论：
1. 「引用的含义」= 引用创建/确认时所钉扎的目标身份与版本语义，不随目标侧变化而漂移；
2. 目标侧一切变化只产生**元数据与待办**（§2.4），不产生引用侧的自动变更；
3. 该原则对全部引用类别生效；display/aggregation 的自动降级（§2.3）属于**读取时视图行为**，不构成对引用记录的修改。

## 2.10 O-09 语义映射（R5 重写，撤销 V0.1「同一语义两个名字」表述）

三个概念各自独立，不得混淆：

| 概念 | 语义 | 现役存储落位 | 关系 |
|---|---|---|---|
| `revision_context` | **引用契约的版本选择语义**（显式声明 Pinned/LatestPublished） | 无单一对应列——由存储层组合表达 | 抽象契约层 |
| `target_revision_id` | **Pinned 模式下的具体目标 Revision** | 现役列（pc.source/projc.source/kb.memory_ref 等） | revision_context=Pinned 的存储落位之一 |
| `revision_missing_reason` | **目标 Revision 不可用时的失效原因记录** | 现役列 | 独立语义：失效原因，**不是版本选择** |

- 抽象契约 ↔ 存储字段的映射关系：Pinned → `target_revision_id`（不可用→`revision_missing_reason`）；LatestPublished → 存储表达方式**留待 schema 设计阶段**（不影响契约层定义）。
- 禁止在文档或代码中把「目标版本」与「失效原因」当作同一语义的两个名字（V0.1 表述作废）。
