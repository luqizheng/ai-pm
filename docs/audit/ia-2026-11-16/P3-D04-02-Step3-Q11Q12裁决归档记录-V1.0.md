## Q-11：approved → rejected 是否允许

**正式裁决：选择 A——禁止翻转。**

1. `approved → rejected` 是**非法状态转换**；
2. Proposal 一经批准，不允许通过原 Proposal 撤销批准并改为 rejected；
3. 批准后的变更意图，应在发布后通过新 Proposal 提出修订；
4. 决策事实保持线性，不允许原批准记录发生反向翻转；
5. 本裁决与此前 Q-02b（禁止 rejected→approved）共同约束状态转换，但**不扩大其他状态转换的合法性**。

**影响范围**：状态机 T-05（重决互改）正式废止并删除；approved 与 rejected 均为「决策终局态」；decide 接口目标语义=仅 submitted→approved / submitted→rejected 两条决策转换+同态幂等；现状 decide 互改行为=**GAP-35 实现差距（全部已裁决，实施批收敛）**；approved→withdrawn 的非法定性维持设计规则推导（Q-11 未涉及、不扩大）。

## Q-12：submitted → expired 触发机制与主体权限

**正式裁决：选择模式 A——仅人工触发。**

1. `submitted → expired` **仅允许人工触发**；
2. 触发主体必须是**具备相应作用域授权的 A3 授权人**；
3. 必须执行 A3 权限检查；不满足权限时必须拒绝，采用 **fail-closed**；
4. `expired_reason` **必须提供，不允许为空**；
5. **V1 不引入系统自动到期机制，不建立自动到期巡检任务**；
6. 到期处置不等同于批准或拒绝，**不赋予 AI 审批权**。

**影响范围**：状态机 T-10 定稿（触发主体=真人 A3、reason 必填、无自动到期）；**GAP-36 裁决齐备**（转换入口+权限门[A3 fail-closed]+expired_at/expired_reason 承载+同事务审计+测试——全部进入实施批）；Q-12 派生的三模式选择闭合（模式 B/C 不采用）；expired_reason 必填与 Q-04 指纹无冲突（expire 不产生指纹/账本语义）。
