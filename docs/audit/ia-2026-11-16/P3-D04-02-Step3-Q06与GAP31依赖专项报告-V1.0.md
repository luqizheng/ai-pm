### 2.2 设计包内部矛盾（=问题清单 I-1，阻塞冻结验收）

```
设计方案 V1.0.7（维持 v1.0.2/3 §D6.5）        D6.6 核验 V1.1 §4
「显式补发布：调用方给定（现状保持）」   ⟷   「{pc|projc}-decision:{proposal_id} 确定性派生，
                                          禁调用方任意——GAP-31 校验」
```

- 对 **close 链**两文一致（派生，CODE FACT 在位）；
- 对 **显式补发布**两文相反：若键禁调用方任意→显式补发布须服务端派生同款键（或该入口本身取消）；若保留调用方给定→fail-closed 校验必须为该入口开非派生键通道，GAP-31-A 规则须改写；
- GAP-31-A（V1.0.11 拆分）声称「规则层闭合、不依赖 Q-06」——**该断言仅对 close 链成立**；31-A 的验收标准（校验器接受什么键）依赖 I-1 收口。

## 四、结论

1. 「不得仅凭 D6.5 推断 Q-06 已解决」——成立：Q-06 原始项①至今未裁；
2. GAP-31 **不阻塞设计冻结的技术设计本体**，但 **31-A 的验收文本依赖 I-1 收口**，而 I-1 属设计包自洽缺陷，须在冻结验收前修订（推荐口径：显式补发布键改服务端派生，对齐 D6.6 V1.1；最终由项目负责人确认）；
3. 处置路径：负责人一次裁决 Q-06（含范围确认①②③+键来源选择）→ 修订 §D6.5/总账 → 31-A/31-B 边界定稿。
