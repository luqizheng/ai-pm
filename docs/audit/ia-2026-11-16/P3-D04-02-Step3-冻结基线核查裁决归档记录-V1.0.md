## D-4：cognition_revision / version_member 保护缺口——设立 GAP-37

**裁决：同意设立。**

- **GAP-37-A**：ProjC cognition_revision 增加 UPDATE/DELETE immutable 保护；
- **GAP-37-B**：ProjC version_member 增加 UPDATE/DELETE immutable 保护；
- 两子项**独立验收**；目标保护=同款 `BEFORE DELETE OR UPDATE ... FOR EACH ROW EXECUTE FUNCTION projc.forbid_row_update()`（函数 0025:329 已在位）；实施批归属建议=Schema/API 阶段（可与 GAP-04 同批，纯增量零数据迁移）；
- 验收三类：①UPDATE/DELETE 探针均被数据库拒绝；②镜像保护清单测试（ProjC 守卫集合与 pc 真源清单一致）；③projc_formal_chain 全量回归；
- **追加验收维度（正式登记时写入）**：验证保护范围与正式事实生命周期一致——普通字段 UPDATE 拒绝、DELETE 拒绝、无绕过触发器的写入方式或特殊执行权限、INSERT 与既有发布流程不受不必要影响、PC/ProjC 保护**语义**真一致（非仅触发器名称一致）；
- 实施设计中须核实触发器函数的实际行为、触发时机与异常语义，不得仅凭函数名视为验收完成；
- 边界：GAP-37 当前为**建议编号**，正式编号与总账登记由总账维护者执行（总账 V1.2 编号规则下建议使用 GAP-37；GAP-34 空置不占用）；设立≠现在修改代码/Migration——实施仍须后续独立授权。
