# Part 1（Step 1）：目标领域对象分类

## 1.1 五形态通用模型与各域形态配置（R1 修正 + R14/R15 修正）

五形态关系：

```
对象身份 Object（稳定，不含正文）
   └── 内容版本 Revision（对象内容的一次版本，正式化后不可变）
   提案 Proposal（变更意图 + 变更集合；指向对象/Revision，不是 Revision 本身）
        ──▶ 人工决策 Decision（针对该提案或确认对象的不可变事实，append-only）
             ──▶ 正式发布版本 Publication（适用域对已确认内容的不可变快照）
```

**形态概念与域内载体分离（R1 核心）**：五个形态是概念层；每个域选择自己的**载体**实现概念。「载体复用 ≠ 形态合并」——一个物理对象可同时承载两个形态的角色，但概念上仍是两个形态、两条语义。

**候选 Revision ≠ Proposal（R14）**：一个 Revision 处于候选状态（等待确认）只说明它是 Candidate Revision；Proposal 还须承载变更意图与变更集合。域可以**不设 Proposal 形态**（候选 Revision 直达确认门），这不构成形态缺失，是合法的载体配置。

各域形态配置（●=独立载体；◐=由其他形态的载体兼任【载体复用】；—=该域不设此形态）：

|---|---|---|---|---|---|---|
| 对象身份 | ● | ● | ●（Source/Document/Memory） | ● | ● | ● |
| 内容版本 | ● | ● | ● | ● | ● | ● |

| **Decision（决策事实）** | Revision 决策锚定字段：document_revision.confirmed_by + published_at（0006 CHECK：published⇔双非空、非 published⇔双空）【R26：published_at 语义=发布生效时间，确认决策时间与之概念分离】；memory_revision.review_status + reviewed_by + reviewed_at（PENDING_REVIEW⇔reviewed_by 空；**通过/拒绝双向结局均为 Decision 事实**）。**Document Reject 无锚定载体=登记缺口（R26）** | Revision 不可变守卫（0006:83-84 禁改已确认字段；memory K4 白名单+单向状态机） | 被确认对象✓、具体 Revision✓（锚定于该 revision 行）、决策结果✓（published/review_status 通过/拒绝）、操作者✓（confirmed_by/reviewed_by→core.principal）、决策时间✓（published_at/reviewed_at）——**Reject 结局在缺口闭合前不满足本列全部✓，落地归 Schema 阶段** |
| **Audit（审计证明）** | governance.audit_log / tenant_audit_log 追加行 | append-only 审计纪律 | 证明「决策操作发生过」及操作上下文；**不是** Decision 本身 |
| **状态翻转（结果应用）** | document_revision.status draft→published；memory_revision.review_status 翻转 | 单向状态机 | 决策的**结果应用**；可由 Decision 锚定字段推导，不是独立事实 |

**Reject 载体闭合（R26，P0-01）**：KB Decision 覆盖**全部正式审核结局**——Accept（确认/通过）与 Reject（拒绝）；KB 现役审核结局仅此两类，新增结局类型=新裁决。**每种结局必须是 append-only 决策事实（对象+Revision+outcome+操作者+决策时间），Audit 只是决策发生的证明，不是任何结局的决策事实载体**：

- Document Accept：载体=confirmed_by + 决策时间（现状与 published_at 同事务压缩承载——概念上**确认决策时间 ≠ 发布生效时间 ≠ 审核时间**，三者分离，字段级表达归 Schema 阶段）；
- Document Reject：**现状无 Revision 锚定载体=如实登记的模型缺口**。概念契约本批闭合：Reject 与 Accept 同等地位，必须产生锚定被拒 Revision、outcome=reject 的不可变决策事实；缺口落地（独立决策记录或结构化审计）为 Schema/API 阶段的强制闭合项；**缺口闭合前，仅有 Audit 的 Reject 不满足 §0.2 Decision 定义**；
- Memory：review_status 通过/拒绝双向 + reviewed_by + reviewed_at，Accept/Reject 均有载体。

Reject 理由（适用时）由审计 payload 与审核流程记录承载——理由记录是决策的补充信息，**不能替代决策事实本身**。概念层 Decision 不因现状无独立表而缺失，但 Document Reject 载体缺口必须显式存在，并被后续阶段视为待闭合项。

> 设计说明：cognition 两域五形态齐全（P3-11 已验证机制）；KB/Delivery/Design 不强加 Publication——只有需要「一组对象整体快照语义」的域才设该形态。

## 1.3 五形态间的形成路径与不变量（R2/R3 修正 + R18 增补）

两条形成路径，终点都是「正式」：

```
路径 A（AI 提案）：AI 分析/提取 ──▶ Proposal（附证据与来源钉扎）──▶ 人工 Decision
路径 B（人工直接）：授权人工起草 Revision ──▶ L1 自确认 或 L2 审批（=Decision）
路径 A/B 汇合 ──▶ 正式化（认知域=Publication 成员；KB=confirm/review 翻转；交付设计域=current 指针推进）
```

通用不变量：
1. 身份不含正文；改正文必产生新 Revision（G-06）；**【R18】任何已存在的 Revision 一经产生即不可覆盖——「draft upsert」的复用仅指内容寻址去重（同 hash 复用既有行），不得改写任何既有 Revision 的内容；【R32】去重仅发生于同一 Object 的版本创建范围内**——不同 Object 始终拥有各自独立的 Revision 身份，不因正文 hash 相同而合并 Revision；hash 是内容相等性判断，**不构成 Revision 身份标识**（Revision 身份=其所属对象版本链中的位置）；
2. **Decision 是不可变的历史事实（append-only）**：不可变指历史决策记录本身；同一对象再次发生决策时产生**新决策记录**，不得覆盖、改写或替代历史记录；当前有效决策由记录序列推导（R3）；
3. **AI 能力三级（R2）**：
   - AI **可以**创建领域允许自动登记的基础资产（如 KB Source 登记、来源/证据登记）；
   - AI **可以**创建候选内容与提案（draft/proposal，止于待确认层）；
   - AI **不得**绕过人工确认门完成需要人工确认的正式认知采纳、审批与发布；
   - 本条只做能力分层表述，**不改变 KB/PC/ProjC 已冻结的人工确认边界**（各域门清单以冻结裁决为准）；
4. 引用创建时按引用类别钉扎目标 Revision（§2.2/§2.3）；
5. 正式化后历史不可覆盖，替代走显式状态（superseded/deprecated），不删除。

3. 业务键的定位：**域内业务/展示标识**，可用于域内 UI 与深链；跨域引用一律用 `target_object_id`。
4. 与冻结的兼容性：本解释**不新增字段、不扩展第五字段**，四字段契约原样；冻结文本中的斜线记法由本条收窄为唯一解释。

## 2.2 版本语义：三层规则（R12 修正，撤销「所有组合均合法」笼统表述）

**第 1 层：引用类别 → 允许的版本模式（合法性约束所在层，见 §2.3 类别表）**

引用的合法性首先由其类别决定允许的版本模式；类别与模式不匹配=非法契约（INVALID_CONTRACT）。

**第 2 层：Reference Version Mode（版本选择模式，属于引用本身，经 revision_context 显式声明）**

| 模式 | revision_context 表达 | 目标版本选择方式 |
|---|---|---|
| **Pinned（钉扎）** | `{mode: pinned, revision: <明确 Revision 标识>}` | 解析到钉扎的具体 Revision；不可达 → REV_MISSING |
| **LatestPublished（最新已发布）** | `{mode: latest_published}` | **动态选择器**：每次解析返回目标域正式化机制下的**当前有效 Revision**（认知域=当前 Publication 成员；KB=已确认 Revision；Delivery/Design=已批准 Revision）——具体 Revision 可随目标演进变化，选择器语义本身不变 |

- LatestPublished **必须显式声明**；revision_context 为空/缺 mode = 非法契约，**不得隐式推断**。
- LatestPublished **只允许用于非正式依据**的展示、聚合和统计场景；**不得成为确认、审批、发布或正式认知的依据**。
- 依据类引用（evidence/basis）强制 Pinned。

**第 3 层：Resolver Operation Intent（解析操作意图，属于一次 resolve 调用，经 ctx.intent 传入）**

| intent | 用途 | 影响 |
|---|---|---|
| READ | 读取目标内容/详情 | 权限判定+返回内容（按目标域策略） |
| NAVIGATE | 导航/跳转 | 权限判定+返回定位信息 |
| ITERATE | 统一检索聚合遍历 | 权限过滤+强制携带领域/身份/版本元数据【冻结 R-08】 |

**正交性的准确表述（R12）**：intent 不改变版本选择（第 2 层结果与 intent 无关）；mode 不改变权限判定（权限只由 §2.6 闭环决定）。正交性**不推出**「所有组合合法」——组合合法性由第 1 层（类别→模式）约束。

## 2.3 引用类别与不可达处理（R6 + R12/R19 修正）

**类别语义边界本批冻结（R19）**：类别集合与下表全部语义、版本模式约束、不可达处理为本批冻结内容；扩展新类别=新裁决；物理登记载体后置（P6 已裁决：物理载体归 Schema/API 与 S4，类别语义/约束/归属本批明确）。**引用关系一经定义，其类别不得随读取请求改变**——类别属于引用的定义，不属于读取行为。

| 类别 | 语义 | 允许的版本模式（R12 第 1 层） | 目标 UNREACHABLE 时处理 | 人工待办 |
|---|---|---|---|---|
| **evidence 证据** | 支持认知的历史事实锚 | 仅 Pinned | 降级为**历史锚永久保留**（引用记录+失效原因留痕）；不重定向 | 无（审计留痕） |
| **basis 依据** | 正式确认/审批所依赖的目标 | 仅 Pinned | 引用域产生待人工处理；目标恢复或显式重定向前，依赖它的业务动作按各域规则阻断或警示 | **是** |
| **association 关联** | 对象间业务关联 | 仅 Pinned | 失效标记；重定向须引用域显式变更 | 由引用域决定 |
| **display 展示** | UI 展示/导航 | Pinned 或 LatestPublished | **按版本模式分治（R27）**：Pinned→仅隐藏/占位/不可用提示；LatestPublished→按目标域策略隐藏/占位/展示降级 | 无 |
| **aggregation 聚合统计** | 计数/汇总 | Pinned 或 LatestPublished（默认 LatestPublished；历史口径统计用 Pinned） | 从统计中排除并计数留痕 | 无 |

**display 类降级的版本模式分治（R27，P0-02）**：「自动降级」按版本模式分治，禁止一刀切回退：
1. **Pinned + UNREACHABLE**：仅允许隐藏、占位或显示不可用状态；**不得将其他 Revision 作为原引用的解析结果返回**——引用声明的是「展示对象 X 的 R1」，Resolver 静默返回 R2 即把引用含义改为「展示 X 的 R2」，直接违反 §2.9 引用稳定性原则；
2. **LatestPublished + UNREACHABLE**：可按目标域策略隐藏、占位或采用明确规定的展示降级行为；
3. UI 出于用户体验展示其他可用版本时，必须将其标记为**独立的降级展示结果**，不得伪装为原引用的解析结果；
4. 降级展示**不得改写 DomainRef**，不得使引用关系看起来仍指向原 Pinned Revision。

非法组合示例（R12）：LatestPublished+evidence（无论 intent）=非法；LatestPublished+basis=非法；LatestPublished+association=非法；Pinned/LatestPublished+display+READ=合法；LatestPublished+aggregation+ITERATE=合法。

**历史锚保留 ≠ 目标内容可访问性 ≠ 永久内容保留（P4 措辞收敛）**：永久保留的是**历史引用事实**（引用记录及其失效原因——审计优先）；目标内容的访问始终受目标域权限与目标存续约束（可能 DENIED 或不存在）；**目标内容、正文或个人数据的实际保留期限服从系统级审计、数据治理与删除政策**——引用事实的审计保留与目标内容的保留政策是两件事。

## 2.4 引用生命周期状态（R13 重构：主状态 + 生命周期标记 + 调用错误）

**结果模型（R13）**：一次引用解析的结局分两类：

**A. 调用错误（CallError）——Resolver 未执行**（契约层拒绝发生在解析之前，不存在解析结果，无 status）：

| CallError | 触发 |
|---|---|
| INVALID_CONTRACT | 契约非法：revision_context 缺 mode / 类别不允许声明的 mode（§2.3 第 1 层）/ 字段非法 |
| DOMAIN_NOT_OPEN | 目标域未开放、非目标侧域、或不存在于注册表 |

调用方以调用失败形式获得（如 Result::Err / 4xx），**不进入 Resolver 状态枚举**。

**B. 解析结果（Resolution）——Resolver 已执行**：

| 主状态 status | 判定 | 语义 |
|---|---|---|
| VALID | 可达+授权成功 | 正常返回目标内容/定位；**可携带 lifecycle_flags（可多个同时成立）** |
| DENIED | 权限闭环任一不满足（且目标域 existence_visible=true） | **最小信息返回**（R7）：不默认暴露存在性/类型/版本/废弃/替代关系；内部诊断（哪一项闭环失败）为受保护信息，不直接暴露 |
| UNREACHABLE | 删除/不存在/锚缺失/**或**权限不足但 existence_visible=false | **区分两件事**：历史锚保留（引用记录+原因，按 §2.3 类别处理）≠ 目标内容可访问（不可访问）；target 字段返回规则见下方三层可见性（R34） |

**lifecycle_flags（仅 status=VALID 可非空；多维并存，互不互斥）**：

| 标记 | 判定 | 语义 |
|---|---|---|
| drifted | Pinned Revision 与目标对象**当前有效正式 Revision** 存在差异【R30】——草稿/Candidate Revision 不触发；「当前有效 Revision」由目标域定义（PC/ProjC=当前生效 Publication 成员；KB=已确认 Revision；Delivery=已确认 Requirement Revision；Design=已批准 Design/ADR Revision） | **版本差异提示，不等于引用失效**：引用仍有效、内容仍返回；携带 drift.current_effective_revision_id |
| superseded | 目标对象被替代 | **保留原目标，不自动重定向**：内容可返回；携带 superseded_by 替代链——**链上每个对象独立权限裁剪（R35），无权后继以裁剪信息返回** |
| deprecated | 目标废弃但仍可达 | 返回内容+废弃标记；**不代表允许所有新引用与所有业务操作**——新引用与操作限制由目标域策略与 L3 冻结规则决定；携带 deprecated_at |

多维并存示例（P0-04 问题 C 的解答）：Pinned 目标已被替代、原 Revision 非最新、对象同时已废弃 → status=VALID，lifecycle_flags={drifted, superseded, deprecated}，三项元数据并存返回。**不再定义状态优先级**——它们是不同维度的属性，不是互斥状态。

**存在性不可区分规则（R20，P1-06）**：目标域 existence_visible 策略决定 DENIED 与 UNREACHABLE 的可区分性——
- existence_visible=false（默认【P7 已裁决：默认不可见逐域放开】）：权限不足的对象**统一返回 UNREACHABLE(NOT_FOUND)**，与真不存在的对象不可区分（防存在性探测）；
- existence_visible=true（目标域显式放开）：方可用 DENIED+最小信息（可见字段仍按最小信息边界裁剪）。

**UNREACHABLE 的 target 字段规则（R34，P1-05——三层可见性独立判定）**：引用锚、目标身份、目标内容是三个不同层次的可见性判断，不得用同一开关：
- **引用锚**：引用记录本身及其原始目标身份（§2.3 历史锚）——永久保留；Resolver/引用域可返回原始锚身份，但不返回目标正文；
- **目标身份**：对象是否存在且允许暴露——NOT_FOUND（真不存在或伪装）时 target **必须全 null**，existence_visible=false 下不得暴露任何身份字段；REV_MISSING 仅在调用方已通过权限判定且目标身份允许暴露时，可返回 target 身份字段（domain/object_type/object_id）而 revision 字段为空；身份不允许暴露时统一返回 NOT_FOUND，**不得借 REV_MISSING 泄露对象存在性**；
- **目标内容**：指定 Revision 是否存在且允许读取——任何情况下不满足读取条件即不返回内容。

**待办产生**：由引用域决定是否产生人工待办及后续处理（默认规则见 §2.3 类别表；引用域可按自身治理收紧，不得放松 evidence/basis 的下限）。

## 2.5 替代与重定向语义（V0.1 维持 + R8/R9 强化）

1. 目标对象替代：旧引用不失效、不自动重定向；Resolver 返回替代链（经 superseded 标记，R13）——**【R35】替代链是目标对象的关联元数据，不是无条件公开的对象列表：链上每个目标对象独立执行权限闭环（R23 逐边授权原则的扩展），调用方无权访问的后继对象以裁剪后的替代信息返回（计数/占位/不可见标记），不泄露其完整身份与内容**；
2. 重定向=引用域内显式变更（走引用域自身提案/确认流程，人工决策留痕）——**该写操作由引用域命令入口执行，Resolver 不承担（R22）**；
3. 删除目标：认知域/KB 禁删【冻结现状】；Git 知识空间文档可删——被引用关系由引用域按 §2.3 收 UNREACHABLE 处理；无级联删除、无自动改写；
4. 引用域对象自身的废弃/替代不影响其持有的对外引用记录（历史锚保留）。

## 2.6 权限语义（冻结红线二 + 权限闭环 + R7 + R21/R22/R23）

- 引用关系本身不构成任何授权凭证。
- 跨域操作须同时满足：调用方授权 + 目标领域授权 + 目标对象当前状态约束。
- **【R21】权限上下文可信来源**：ctx.caller/tenant/project 必须由**服务端可信身份上下文**建立（认证层惯例，如 AuthedPrincipal.tenant_id 来源纪律）；Resolver 不得信任调用方自行传入的身份、租户或项目声明——传入参数只能作为解析目标，不能作为授权主体。
- **【R22】读写边界**：Resolver 是**只读解析服务**——确认、审批、重定向、引用关系变更等一切写操作，必须由对应领域的命令入口授权并执行；Resolver 不承载写语义、不产生业务状态变更。
- **【R23】逐边授权**：NAVIGATE/ITERATE 遍历中，**每条引用边、每个目标对象独立执行权限闭环**，不得继承入口对象或上一跳的授权结果；多跳遍历逐边判定。
- 权限回收后：引用保留（身份锚）；解析按 R20 存在性策略返回 DENIED 或伪装 UNREACHABLE；统一检索按权限过滤【冻结 R-08】；不因权限变化删除或改写引用。

## 2.7 Resolver 契约（供 P3-10 / O-01；R13/R21/R23 修订）

```
resolve(ref: DomainRef, ctx: ResolveContext) -> Result<Resolution, CallError>

ResolveContext（全部由服务端可信身份上下文建立【R21】）:
  caller: PrincipalId            // 服务端认证解析，非调用方声明
  tenant: TenantId               // 同上
  project: Option<ProjectId>     // 服务端解析的授权输入
  intent: READ | NAVIGATE | ITERATE

CallError（调用层拒绝，Resolver 未执行【R13】）:
  INVALID_CONTRACT   // 缺 mode / 类别不允许该 mode / 字段非法
  DOMAIN_NOT_OPEN    // 目标域未开放/未登记/非目标侧

Resolution（解析结果【R13】）:
  status: VALID | DENIED | UNREACHABLE
  lifecycle_flags: { drifted?, superseded?, deprecated? }   // 仅 VALID 可非空；多维并存
  flag_metadata: {
    drift:      { current_effective_revision_id? },          // 【R30】当前有效正式 Revision，非「最新 Revision」
    superseded: { superseded_by? },                          // 【R35】链上对象按权限逐个裁剪
    deprecated: { deprecated_at? }
  }                                                          // 各项按调用方可获知范围裁剪
  target: { domain, object_type, object_id, revision_id?, version_label? } | null
          // DENIED 时按最小信息边界，默认 null
          // 【R34】UNREACHABLE：NOT_FOUND→必须全 null；REV_MISSING→仅身份字段、仅目标身份允许暴露时
  error: NOT_FOUND | REV_MISSING | null                      // 仅 UNREACHABLE 非空；披露顺序见【R31】
  permission_diagnostics: { caller_ok, domain_ok, state_ok } | null
                                                             // 【R31】内部诊断数据，不对普通调用方输出；
                                                             // 仅受信任的内部诊断通道可读，披露策略归 P3-D05
```

- 每域实现**本域 resolver**；引用方禁止跨 schema 直查【冻结】。
- **【R22】Resolver 只读**：无任何写副作用；引用变更/重定向走各域命令入口。
- **【R31】权限判定先于原因披露**：存在性与权限判定完成后，才允许返回 REV_MISSING；调用方未通过权限判定时一律按 NOT_FOUND 处理，不得借 Revision 缺失原因泄露对象存在性。DENIED 对外仅含目标域策略允许的最小信息（R7），permission_diagnostics 不作为普通调用方可见结果。
- **【R23】逐边授权**：遍历实现必须对每条边独立调用目标域 resolver 权限判定，禁止批量继承。
- ITERATE 结果必须携带原始领域/身份/版本/权限判断元数据【冻结 R-08】，且元数据本身受 R7 最小信息边界约束。
- 存在性可见策略（existence_visible）属目标域安全策略，默认不可见【P7 已裁决】，P3-D05 治理规范承接细化。

## 2.8 校验分层（V0.1 维持，S4 展开）

契约层（domain 注册表 + type 在目标域注册表 + revision_context 模式合法 + **类别允许该 mode（R12 第 1 层）**）；各域 DB 层（仅本域完整性，跨域一律无 FK）；Resolver 层（存在性/版本/权限/状态读取时验证）。

## 2.9 Reference Stability Principle（引用稳定性原则，R9 + R24 修订【随本批待审】）

> 正式引用一旦被确认或随正式对象发布，其目标身份与版本语义必须保持稳定。目标对象后续发生版本更新、替代、废弃、权限变化或删除，不得静默改变原引用的含义。任何重定向、版本替换或引用关系修改，必须由引用所属领域发起新的显式变更，并经过该领域规定的确认机制。LatestPublished 仅适用于非正式依据场景。

**【R24】对 LatestPublished 的适用方式**：本原则保护的是**引用的定义与选择语义**，不是「解析结果永远同一个 Revision」——
- Pinned 引用：稳定到具体 Revision（目标不可达时按 §2.3 处理，不静默换锚）；
- LatestPublished 引用：稳定的是「始终指向目标当前已发布版本」这一**选择器定义**；每次解析得到的具体 Revision 可随目标演进变化——因其不得作为正式依据（§2.2），这种变化不改变任何正式语义，不违反本原则；
- 由此，引用稳定性保障的对象=引用语义；具体 Revision 的动态性被限制在非正式依据场景内。

推论：
1. 「引用的含义」= 引用创建/确认时所声明的目标身份与版本选择语义，不随目标侧变化而漂移；
2. 目标侧一切变化只产生**元数据与待办**（§2.4），不产生引用侧的自动变更；
3. 该原则对全部引用类别生效；display/aggregation 的自动降级（§2.3）属于**读取时视图行为**，不构成对引用记录的修改；**【R27】Pinned 引用的降级仅限隐藏/占位/不可用提示——以其他 Revision 充当原引用的解析结果属于静默换锚，直接违反本原则，不属「读取时视图行为」**。

## 2.10 O-09 语义映射（R5 重写，维持；表述与 R13 结果模型对齐）

三个概念各自独立，不得混淆：

| 概念 | 语义 | 现役存储落位 | 关系 |
|---|---|---|---|
| `revision_context` | **引用契约的版本选择语义**（显式声明 Pinned/LatestPublished） | 无单一对应列——由存储层组合表达 | 抽象契约层 |
| `target_revision_id` | **Pinned 模式下的具体目标 Revision** | 现役列（pc.source/projc.source/kb.memory_ref 等） | revision_context=Pinned 的存储落位之一 |
| `revision_missing_reason` | **目标 Revision 不可用时的失效原因记录**（对应 Resolution 的 UNREACHABLE/REV_MISSING 路径） | 现役列 | 独立语义：失效原因，**不是版本选择** |

- 抽象契约 ↔ 存储字段的映射关系：Pinned → `target_revision_id`（不可用→`revision_missing_reason`）；LatestPublished → 存储表达方式**留待 schema 设计阶段**（不影响契约层定义）。
- 禁止在文档或代码中把「目标版本」与「失效原因」当作同一语义的两个名字（V0.1 表述作废）。
