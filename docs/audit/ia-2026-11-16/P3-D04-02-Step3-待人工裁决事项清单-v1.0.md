## 阻塞设计冻结的裁决（4 项）

### Q-01：起草段幂等锚形态（F-04 闭合方案，GAP-01/02/23/27）

- **问题**：AI 提案产生→物化→提交段（非发布段）的意图幂等用什么机制钉扎？
- **事实**：发布段 write_operation 账本（UNIQUE+状态机触发器+completed 短路重放）已验证；起草段现状=advisory 串行+候选排除+事件幂等键（同源重放有防护）；身份综合链完全无防护（同轮重跑→重复提案）。
- **备选**：A=扩展 write_operation 账本（新命令 `{pc|projc}_propose`/`_submit`，operation_id=`{domain}-{chain}:{业务锚}`）｜B=维持现状（advisory+排除）｜C=proposal 表加 idempotency_key 唯一列。
- **利弊**：A=复用全套已验证机制、与发布段统一模型、审计/重放/自愈现成，代价是 Schema 阶段扩 CHECK+4 个调用点改造；B=零改动但身份链裸奔、不满足任务书「不得止步于现状记录」；C=行级直锚但双机制并存、语义割裂。
- **推荐**：**A**。
- **影响范围**：D6 全节定稿、GAP-01/02/23/27 实施批、write_operation CHECK 迁移一张。
- **阻塞**：是（D6 未定稿则 Step 3 设计不完整）。

### Q-02：rejected 提案复活语义（D1.2 T-05/R1-a）

- **问题**：rejected 提案是否允许 resubmit（draft→submitted 之外的复活路径）？
- **事实**：现实现 submit 仅接受 draft；rejected 出路=报告关闭前 re-decide 翻转（T-05）或另起新提案；决策事实 append-only（R36）。
- **备选**：A=维持（rejected 不 resubmit）｜B=开放 rejected→submitted（需重走校验链+新审批行）。
- **利弊**：A=决策事实可追溯性完整、实现零改动；B=少建一条新提案的便利，但引入「驳回后原对象复活」的语义灰区（同一提案被多次驳回/批准的审批面噪音）。
- **推荐**：**A**（维持现状=设计零变更）。
- **影响范围**：D1 状态机终稿、submit_proposal 契约描述。
- **阻塞**：是（状态机定稿前提）。

### Q-03：expired 状态语义（GAP-03）

- **问题**：proposal CHECK 值域中的 expired 无 setter、无触发条件——定义还是移除？
- **事实**：仅一处查询排除引用（propose_from_analysis 候选 SQL）；无任何代码路径置此态。
- **备选**：A=定义自动过期策略（基线迁移后 N 天未决→expired，需巡检/触发器）｜B=从值域移除（Schema 阶段 CHECK 微迁移）。
- **利弊**：A=闭环「僵尸提案」清理但引入隐性状态转移面（违背「服务层唯一推进面」原则）；B=状态面最小化，僵尸提案由 close 批量 withdraw 兜底（已存在）。
- **推荐**：**B**（移除；withdraw 已覆盖未决提案收口）。
- **影响范围**：D1 状态机值域、GAP-03/28 实施批。
- **阻塞**：是（状态机值域定稿前提）。

### Q-04：重复提交语义（GAP-07）

- **问题**：submitted 态重复 submit 返回 409 还是同态幂等返回？
- **事实**：decide 已实现同态重放幂等（approved→再 approve 返回既有事实）；submit 无同态分支（非 draft 一律 409）。
- **备选**：A=同态幂等（submitted+同 hash+同基线→返回既有 receipt）｜B=维持 409。
- **利弊**：A=调用方超时重试体验一致（四段幂等语义对齐）；B=零改动、409 严格区分「状态冲突」与「幂等命中」。
- **推荐**：**A**（与 D6 统一幂等模型对齐）。
- **影响范围**：D6.3、GAP-07 实施批。
- **阻塞**：是（D6 提交段定稿前提）。
