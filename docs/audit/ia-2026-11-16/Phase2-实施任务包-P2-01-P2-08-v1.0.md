# P2-04：审阅交互迁移（核心验收=关闭语义七条）

**目标：** KB 确认 / PC 决策 / 报告关闭在 Analysis 详情页承载，复用三组既有端点，零后端改动。

**前置：** P2-03（交互挂在详情节 2/3/6）。

**端点（原样，不得改请求/响应契约）：**

| 交互 | 端点 | 调用方迁移 |
|---|---|---|
| KB 确认 | `POST /v1/kb/documents/{d}/revisions/{r}/confirm`（api/knowledge.ts:64） | confirmKb（现 panel :219-238；按钮条件 `kb_revision.status==='draft' && row.status==='analyzed'`） |
| PC 提案批准/驳回 | `POST /v1/pc/proposals/{id}/decision`（api/knowledge.ts:270，CAS expected_version_no） | decideProposal（现 :240-261；按钮条件 :546-553 = analyzed 且 status∈{submitted,approved,rejected}，**可互转显隐条件原样保留**） |
| 报告关闭 | `POST /v1/pm/analysis-reports/{id}/close`（api/analysis-reports.ts:112） | doClose（现 :280-299 + ConfirmationDialog :632-652） |

**关闭语义七条 = 本卡核心验收（逐条可测）：**

1. 批准=暂记（approvedPending 文案），**不得设计成正式发布**。
2. 开放期批准/驳回可互转（按钮显隐按现条件）。
3. 关闭后冻结（后端 409 frozen；前端 closed 态不渲染决策按钮）。
4. close 时统一发布（回执 applied 计数）。
5. 未决撤回 + KB 草稿拒绝（回执 withdrawn/rejected 计数）。
6. 锚点固化（回执 last_analyzed_commit 短 sha）。
7. 仅 analyzed 可关；409 report_open 报错路径 UI 可见。

**其他：** 前端单飞守卫（acting/closing）等价迁移；确认范式二选一随迁（面板单击或 armOrSubmit 双击），不引入新范式；PC 决策 note 字段按现契约可选；不新增理由字段。

**禁止：** 在 Analysis 页重写状态机；改任何端点身份校验（Z-01 保留登记）；删除 Review Center 决策入口之外的 RC 行为。

**验收：** 交互单测（暂记→互转→冻结状态驱动显隐；409 错误文案路径；关闭回执渲染）；**权限负向**：无权限/非真人 403 时错误态呈现（不重试不吞错）。

**交付：** 交互迁移 + 单测 + 关闭语义七条逐条自查表。

**回滚：** **双侧同步**——本卡只增不减（KnowledgeView 旧面板仍在），回滚=删新交互；旧面板退役在 P2-06 执行，届时回滚须成对恢复。
