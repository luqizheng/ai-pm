## 一、问题 1：测试合法结果集合修正

### 1.1 原测试实际断言（V1.0，如实引用）

```rust
// pc 用例（V1.0 原文）：
let legal = match (p.as_str(), w.as_deref()) {
    ("approved", _) | ("submitted", _) | ("draft", _) | ("withdrawn", _)
    | ("rejected", _) | ("expired", _) | ("failed", _) => true,   // ← 通配
    ("applied", Some("completed")) => true,
    ("applied", Some("pending")) | ("applied", Some("failed")) | ("applied", None) => false,
    _ => false,
};
// projc 用例同构通配。
```

**审阅方指正成立**：`("approved", _)` 通配**会放过 `(approved, completed)` 混合快照**——该组合正是审阅方时间线反例的核心，属**测试缺陷**（业务代码未动，缺陷仅在断言面）。

### 1.2 修正后的合法/非法结果矩阵

**按账本行全生命周期路径逐项定义**（路径依据=独立复核 R1/R2 的 CODE FACT）：

| 账本路径（发布键行） | 提交后可见组合 | 依据 |
|---|---|---|
| 从未发布（行不存在） | `(draft/submitted/approved/withdrawn/rejected/expired, 无行)` | decide/withdraw/expire 无账本写点（CODE FACT：账本仅 publish/起草段建立；起草段键 `-analyze:/-identity:` 不相交） |
| 发布成功 | `(applied, completed)` | 同事务原子（R2） |
| CAS 失配 | `(failed, failed)` | 同事务双 failed（publish.rs:305-325） |
| 子事务回滚 | 行消失 → `(approved, 无行)` | 回滚 |
| 失败后重试成功 | `(applied, completed)`（failed→completed 同事务翻转） | :197-207 重试路径 |
| 事务内中途态（pending） | **不可见**（未提交） | MVCC |

**由上推出全序合法域**（任意已提交观察）：`w=None → p ∈ 未发布族任意`；`w=Some(completed) → p=applied`；`w=Some(failed) → p=failed`；`w=Some(pending) → 不存在已提交来源=非法`。

**本测试构造下的合法域（精确两元）**：测试场景=approved 提案+无历史账本行+一次发布 →
- ✅ `(approved, 无行)`（提交前）
- ✅ `(applied, Some("completed"))`（提交后）
- ❌ 其余一切——**显式含 `(approved, completed)`**（审阅方反例）、`(applied, pending)`、`(applied, failed)`、`(applied, 无行)`。
