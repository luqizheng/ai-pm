## 二、评估过程抓出并修复的两个检索层问题（WP-5 的直接产出）

1. **AND 语义放大跨词边界 bigram 假阴性**：`plainto_tsquery` 把"费率是多少"切出的"率是/是多"与正文 bigram 做 AND——正文没有这两个跨界 bigram → 整查询灭（基线 v0：recall@5=0.167）。**修复**：查询侧改 OR（`to_tsquery` + ` | ` 连接），相关性排序交给 `ts_rank` + 通道复合权重（命中词多者分高）——recall@5 0.167→1.000。**该修复是通用的（对将来真 BM25 同样适用：查询分词策略独立于排序算法）**。
2. **种子零边静默空转**：遍历种子解析成功但零正式边时不输出任何缺口——补 `no_active_edge` gap（RT-011 的"明确报告"闭环）。

## 四、预判（供真实语料到位后的对照假设，不构成结论）

- 合成集 Recall@5 已 1.000——**合成语料上 BM25 无提升空间**（这本身就说明合成集已饱和，进一步评估必须真实语料）。
- MRR 0.741（前位排序有提升空间）：真 BM25 的长度归一化与词频饱和可能在**排序**（非召回）上产生差异；Reranker（G-5）在排序维度的预期收益大于 BM25。
- FTS 的已知短板待真实语料验证：中文长查询的 idf 缺失（ts_rank 无 IDF）、文档长度归一化缺失。
