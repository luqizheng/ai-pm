ADR-VIZ-002 M-2 修订签收单

渲染 Adapter 定位变更：浏览器内产物渲染器 → 服务端 SVG 出图器

修订编号 M-2　·　ADR VIZ-002
签收方 Architecture + Security（双签）
依据 15 号安全审查（实测）+ 专家裁决 2026-11-12
本修订未完成双签前，不得 vendor SeeCode。
  • 这是架构定位变更，不是实现细节——信任边界、执行环境、部署责任、安全验证全部发生变化。
  • 不能将原 ADR 对浏览器内 SeeCode 的安全假设，直接继承为服务端执行的安全结论。两者解决的问题不同：前者是「不可信 HTML 在浏览器沙箱中运行」，后者是「不可信输入在服务端 Node 中执行」。
  • SVG 是静态文件格式，不代表 SVG 内容天然安全。安全证明只能来自静态化检查结果，不能来自扩展名或 MIME 类型。

定位变更对照

维度 原定位（修订前） 新定位（本修订）
执行位置 用户浏览器内（iframe） 服务端渲染 Worker
执行环境 浏览器沙箱 + 独立 Origin + CSP 进程隔离 + 资源限额（§3）
产物形态 交互式 HTML（内含 JS） SVG only（静态，无脚本）
信任边界 产物作为不可信主动内容隔离 输入不可信 + 执行环境需另建隔离
依赖注入 仅浏览器运行时 Node 20 运行时（仅渲染 Worker 镜像）
部署责任 静态产物域 Worker 镜像维护 + Node 运行时安全更新

请逐项确认（12 项）

# 确认项 Architecture Security
1 Adapter B 定位变更为服务端 SVG 出图器（非核心依赖，失败降级不影响 Live 图） ☐ ☐
2 落仓约束：锁定上游版本与 commit；保留 LICENSE / NOTICE / UPSTREAM；业务领域不得直接依赖 tools/seecode/；有明确移除路径（删目录 + 注销 Adapter 即回退 Fallback） ☐ —
3 升级策略：锁版本 + 每季度评估；每次升级必须形成五项记录（版本与 commit / 文件差异 / 依赖与许可变化 / 安全回归 / 契约回归） ☐ ☐
4 运行时边界：Node 20 仅渲染 Worker 镜像；API 服务与普通任务 Worker 不引入；不需要 Chrome / Headless Browser ☐ ☐
5 双测试门禁：Adapter 变更必须通过 viz_artifact_safety + adapter_contract；责任三方划分（开发者改与测 / 技术 Owner 把合并门禁 / Security Owner 维护安全规则与高风险用例） ☐ ☐
6 §3.1 输入属于不可信主动内容；传参一律经 stdin，绝不拼进命令行（防命令注入） — ☐
7 §3.2 服务端执行不继承任何凭据：API 凭据 / 数据库 DSN / 文件服务 token / 业务权限上下文一律不注入子进程 ☐ ☐
8 §3.3 渲染过程不得访问外网（由部署侧网络策略阻断出口） — ☐
9 §3.4 资源限额：执行时间硬超时、内存上限、CPU 并发限制、仅临时目录可写且渲染后清理 ☐ ☐
10 §3.5 SVG 输出必须经独立安全静态化检查（脚本 / 事件处理器 / foreignObject / 外部资源 / 危险 CSS），不以扩展名或 MIME 判定安全 — ☐
11 §3.6 检查失败必须拒绝产物，不得以未检查的 SVG 降级入库；禁止「跳过检查」「改写后再入库」「未检查 SVG 降级」三种做法 ☐ ☐
12 明确「SVG 格式 ≠ 内容安全」：安全证明只来自静态化检查结果 — ☐
