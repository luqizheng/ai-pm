## 1. 使用说明

| 规则 | 说明 |
|---|---|
| 签收主体 | 角色制，姓名在任务分配时登记（ADR §5.1 不虚构人员） |
| 结论三选 | **确认** / **有异议（附具体条目与替代方案）** / **有条件确认（附条件与截止时点）** |
| 异议处理 | 有异议 → 由 Architecture Owner 裁决；涉及架构方向变更 → 触发 §6 专家再介入条件 |
| 证据要求 | 只接受可存在的工件（测试文件/CI 输出/签收件/查询输出），不接受口头确认 |
| 归档 | 签收结论与工件路径登记进本包 §5 回执表 |

### S-4 Security Owner 签收表（ADR-008/010 + V-3′，按 15 号审查修订）

- **待签收**：产物安全**三层**设计——静态化（无 script/foreignObject/on*/外链）、零外网（字体内嵌 + 本地 vendor 编码器）、自绘交互（交互通道不引入产物脚本）+ 输入转义三层防线。
- **必须覆盖的设计要点**：① 产物静态化断言清单（无 `<script>`/`foreignObject`/可执行 `on*`/外部引用/`<use>`·`<image>` 外链）；② 零外网（SVG 字体 base64 内嵌、CLI 用本地 vendor 编码器）；③ 交互通道不得引入任何产物脚本；④ 转义禁盲目预转义 + 注入向量覆盖全部输出位（**补单引号与上下文用例**）。
- **实测已过**：2026-11-12 本地实跑 SeeCode v0.6.3 —— SVG 导出纯 Node、`<script>`=0、真实外链=0、字体内嵌、注入 payload 全部正确转义 → **ADR-VIZ-010 硬门槛解除**。
- **需明确**：重新引入 HTML 产物（浏览器内投递）默认禁止；若将来必须引入，须重走 ADR-008 全套（独立 Origin + sandbox + CSP + postMessage）。

## 6. 专家再介入触发条件（收口）

内部签收期间出现下列任一情况 → 由 Architecture Owner 提交外部专家复核（提交物为**实测结果包**，非设计文档）：

| 触发 | 原因 | 提交物 |
|---|---|---|
| V-3 不过（SeeCode 注入测试失败） | 硬门槛：不得接收不可信 AI Spec；"解释性产物"通道将失去渲染器 → Adapter B 选型需重开 | 注入测试报告 + 转义实测记录 + Fallback 可用性证明 |
| V-1 不过（G6 未达阈值） | DV-2 在线图选型重开（换 Cytoscape / Vue Flow / 其他） | 构建产物体积实测 + 性能 p50/p95 + 固定测试条件表 |
| 出现影响 > B1 的架构变更请求 | 新增业务写路径、需改领域表、触及权威模型 | 变更请求 + ADR 差异说明 |

其余分歧按 §1 内部裁决流程处理，不触发外部复审。
