# PA-06：AI Agent 与人类的协作边界

**决策编号：** PA-06\
**状态：** 已确认（PA-06-01 至 PA-06-06）\
**基线日期：** 2026-11-20

## 1. 目标

明确 AI Agent 在 smark-pm 中的自主权限、人类决策边界，以及 Agent
对事项、正式知识、研发计划、交付验收和异常处理的职责。

本决策遵循平台面向小型、紧密协作研发团队的总体原则：尽可能由 Agent
自主完成常规分析、规划和执行；人类主要介入关键业务取舍、重大方向变化，以及超出
Agent 授权边界的事项。

## 2. 总体原则

### 2.1 人类与 Agent 的职责

-   人类确定业务目标、关键约束和需要人类判断的重大取舍。
-   Agent
    在已确认的业务目标和约束范围内，自主分析、规划、执行、验证和交付。
-   不要求人类对 Agent 的每项方案、每个普通任务或每次常规操作事前批准。
-   Agent 不得擅自改变已确认的业务目标、业务约束或正式业务决策。
-   当操作超出授权范围，或涉及重大业务取舍、重大方向变化时，Agent
    应分析影响并请求人类决策。

### 2.2 自主执行的基本边界

Agent 可以自主决定如何实现已确认的目标，但不能自行改变目标本身。

计划调整、技术实现优化和普通执行异常处理，不应自动升级为人类审批事项；只有当其影响已确认业务目标、交付范围、正式设计约束或重大业务取舍时，才需要人类介入。

## 3. PA-06-01：Agent 自主权限基本原则

**状态：** 已确认\
**选择：** A------完全授权执行

Agent 在已确认的业务目标和约束范围内，可以自主：

-   分析需求并制定研发执行方案；
-   选择技术实现方案；
-   规划和调整任务执行顺序；
-   执行研发任务；
-   根据执行结果进行必要的调整和优化。

上述行为无需人类逐项事前批准。

Agent
不得擅自改变已确认的业务目标或业务约束，也不得自行决定重大业务取舍或重大方向变化。触及这些边界时，应分析影响并请求人类决策。

**核心原则：人类确定目标和关键边界，Agent 在授权范围内自主完成工作。**

## 4. PA-06-02：Agent 自动创建和修改事项的权限

**状态：** 已确认\
**选择：** A------完全授权 Agent 管理执行性事项

Agent 可以自主创建和修改以下执行性事项：

-   Task；
-   Issue；
-   Risk；
-   Blocker。

授权范围包括：

-   创建事项；
-   修改描述和其他普通内容；
-   更新状态；
-   调整优先级；
-   拆分任务；
-   更新事项信息；
-   建立和维护普通关联关系。

上述操作无需人类逐项事前批准。

同时必须遵循 PA-05-04 的关联维护规则：

-   Agent 可以自动建立语义明确的普通关联。
-   重要业务归属或正式关系变更，必须由 Agent 提议并经人类确认。
-   人类明确修改过的关系，Agent 不得擅自覆盖。
-   重要活动应记录在 Activity History。

本项授权针对执行性事项，不代表 Agent 可以无条件修改正式
Requirement、Design 或 Decision。

## 5. PA-06-03：Agent 对正式需求、设计和知识的修改权限

**状态：** 已确认\
**选择：** A------草稿自主维护，实质变更人工确认

### 5.1 Requirement

Agent 可以：

-   自主创建需求草稿；
-   分析、整理和修改需求草稿；
-   自主完成不改变业务含义的文字整理和格式修正。

新增或修改正式需求的业务含义，必须经过人类确认后才能成为正式版本。

### 5.2 Design

Agent 可以：

-   自主创建设计草稿；
-   自主进行技术分析；
-   自主修改设计草稿；
-   自主完成不改变已确认设计约束的普通整理和修正。

改变已确认设计约束或架构方向，必须经过人类确认后才能成为正式版本。

已批准设计范围内的普通实现细节调整，继续遵循 PA-04-06，可由 Agent
自主处理并记录。

### 5.3 Decision

Agent
可以整理决策材料、生成决策记录草稿，但正式业务决策必须由人类作出。Agent
不得代替人类作出或发布正式业务决策。

### 5.4 总体原则

Agent
负责持续维护和演进知识草稿；人类负责确认会改变正式业务含义或重要技术约束的内容。

## 6. PA-06-04：Agent 执行计划与任务调度权限

**状态：** 已确认\
**选择：** A------完全授权 Agent 自主管理执行计划

Agent 可以自主：

-   创建研发任务；
-   拆分和合并任务；
-   调整任务执行顺序；
-   识别依赖并建立阻塞关系；
-   根据执行情况动态调整计划；
-   将任务分配给适合的 Agent；
-   并行执行互不冲突的任务；
-   因技术原因暂停、恢复或重新安排任务。

上述计划和调度行为无需人类逐项事前批准。

### 6.1 目标与计划的边界

计划调整不等于目标调整。

Agent 可以为了更有效地实现既定目标而改变任务拆分、执行顺序、依赖安排和
Agent 分工，但不得擅自改变已确认的业务目标或交付范围。

### 6.2 多 Product 资源竞争

多 Product 出现实质性资源竞争时，继续遵循 PA-04-08：

-   Agent 分析资源竞争和影响；
-   Agent 提出建议；
-   必要时请求相关成员中的任意一人决定优先级；
-   人类明确调整优先级后，Agent 遵循该指示。

不建立跨 Product 优先级委员会或复杂排期审批。

## 7. PA-06-05：Agent 交付、验收与完成权限

**状态：** 已确认\
**采用方案：** Agent 在明确验收标准和授权范围内自主完成交付与验收

### 7.1 Agent 自主权限

Agent 可以自主：

-   判断研发任务是否完成；
-   执行自动化测试和质量检查；
-   根据明确的验收标准判断技术验收结果；
-   在满足完成条件后，将 Task 更新为 Completed；
-   整理交付说明和变更记录；
-   在测试失败或验收不通过时，记录问题、修复并重新执行；
-   对明确、客观、可验证的业务验收条件进行分析和判断。

上述常规交付与验收行为无需人类逐项事前批准。

### 7.2 需要人类介入的情况

-   涉及主观业务判断或重大业务取舍时，请求人类决策。
-   改变正式业务验收标准，必须经过人类确认。
-   Agent 不得通过自行降低验收标准来宣告任务完成。

### 7.3 完成条件

-   代码提交不等于任务完成。
-   任务完成必须满足对应验收标准。
-   测试失败、验收条件未满足或重大问题尚未解决时，不得标记为成功完成。
-   重要交付结果进入 Activity
    History，记录完成状态、验收结果、交付内容和相关证据。

### 7.4 概念区分

研发实现完成、技术验收通过和业务验收通过是不同概念，不得混为一个判断。

对于明确、客观、可验证的业务验收条件，Agent
可以自主验证；对于主观体验、业务取舍或无法可靠自动验证的事项，应请求人类判断。

## 8. PA-06-06：Agent 异常、风险和人工介入机制

**状态：** 已确认\
**采用方案：** Agent
优先自主恢复；无法安全恢复时局部暂停；需要人类判断时再升级请求

### 8.1 普通异常自主处理

对于普通错误和可恢复异常，Agent 可以自主：

-   诊断问题；
-   修复问题；
-   重试操作；
-   调整执行计划。

例如工具调用失败、测试失败和依赖缺失等，不应默认要求人类介入。

### 8.2 重试上限

-   Agent 应设置合理的重试上限，避免无限循环。
-   达到重试上限后，记录失败原因并暂停受影响任务。
-   不应在无法确认安全性的情况下持续重复操作。

### 8.3 局部暂停

-   一个任务受阻时，优先暂停受影响的任务或执行分支。
-   不应无条件停止整个 Project。
-   其他不受影响的任务可以继续执行。

### 8.4 重大风险升级

涉及以下情况时，Agent 应先停止相关操作，并请求人类决策：

-   数据丢失风险；
-   不可逆操作；
-   安全风险；
-   正式业务要求冲突；
-   超出既定授权范围的操作；
-   需要重大业务取舍或重大方向变化的事项。

### 8.5 人类介入请求的内容

Agent 请求人类介入时，应提供足够的决策上下文：

-   问题描述；
-   影响范围；
-   已经尝试的处理方案；
-   可选方案；
-   Agent 的推荐方案及理由。

### 8.6 人类决策后的恢复

-   记录人类决策结果。
-   Agent 根据决策继续执行或调整计划。
-   不要求人类重新安排全部执行计划。
-   继续遵循 PA-03 的决策路由和决策完成规则。

## 9. 与其他架构决策的关系

PA-06 应与以下已确认决策共同执行：

-   **PA-03：** 人类决策请求的参与者路由、任意一位有资格的 Product
    Member 完成日常决策，以及决策完成后的通知规则。
-   **PA-04：** 多 Product
    需求冲突、共享任务验收、技术设计变更和研发优先级规则。
-   **PA-05：** 事项基础模型、领域对象、关联维护、Activity History、Feed
    和已读状态规则。

PA-06 不取代上述规则，也不扩大 Agent 对正式业务决策的权限。

## 11. 总结

PA-06 确立的协作模式是：

**人类负责目标、业务取舍和关键方向；AI Agent
负责分析、规划、研发执行、验证和交付，并在授权范围内自主完成工作闭环。**

系统不应将 Agent 设计成每一步都等待人类批准的执行工具，也不应允许 Agent
越权改变正式业务目标和关键决策。
