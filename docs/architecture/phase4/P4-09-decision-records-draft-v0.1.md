**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **不在本 DR 内裁决**：成员对本 Product 的读取范围细分（→DR-01 子项/O8）；Project 侧只读范围（→DR-03）；敏感区（→DR-05~11）。

- **决策方向〔CONFIRMED 2026-11-19〕**：
  1. 引入 Product 成员资格，来源=Owner 自动 ∪ 直接添加 ∪ Project 继承（每 active Link 一个来源），任一来源有效即成员。

- **影响的其他 DR**：DR-02（来源撤销）、DR-03（只读范围）、P4-02 DR-05 读写分离表（产品侧关联查询权限集是否扩展）。

## DR-02 — 成员资格来源撤销语义（含 Link ended 联动） 〔已撤回 2026-11-19，D-3 → DR-ORG-04〕

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **裁决问题**：多来源资格的撤销规则与即时生效语义。
- **上游冻结约束**：P4-02 DR-02/DR-06（Link ended 终态行保留、team_dissolved 同事务清扫）；P4-02 DR-03 补充 B（实时有效授权、不读缓存）；P4-01 补充 A（Owner 离开 Team 移除检查）。
- **决策方向〔CONFIRMED 2026-11-19〕**：
  1. 退出 Project → 仅撤销该 Project 的继承来源。
  2. Link ended（人工 end 或 team_dissolved 清扫）→ 自动撤销该 Project 的继承来源；清扫路径与 Link 终态化同事务。
  3. 撤销单一来源不影响其余有效来源（并集语义）。
  4. Owner / Tenant Admin 对直接添加来源有直接管理权。
  5. 来源失效后访问权**立即撤销**，后续请求实时重查权限，不依赖旧会话缓存。
- **登记（实施集成点，非本 DR 授权）**：dissolve 清扫集扩展（撤销继承来源）沿 P4-02 DR-06「清扫扩展=实施期登记项」先例登记。
- **影响的其他 DR**：DR-01；P4-02 DR-06（清扫集扩展登记衔接）。

## DR-03 — Product 成员对关联 Project 的完整只读与权限并集 〔已撤回 2026-11-19，D-3 → DR-ORG-04〕

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **裁决问题**：Product 成员对关联 Project 的读面定义；与 Project 原有权限的合成规则。
- **上游冻结约束**：P4-01 DR-06 第 6 条（双向隔离——本 DR 批准=读向穿透的显式修订）；P4-02 DR-05（关联查询端点数据最小化——与本项目级读取通道并存，两通道须区分：关联端点最小字段 ≠ 项目业务内容读取面）；H8（人工确认门，只读不触及）；P4-03 §2.3 铁律 2（PROPOSED，冲突已在 P4-03 附录 B 登记）。
- **决策方向〔CONFIRMED 2026-11-19〕**：
  1. Product 成员对全部直接关联 Project 拥有完整只读：Project 详情、需求、设计、技术认知、任务、其他普通业务内容；以及 §3 清单（Agent 执行记录/分析结论/委派关系/Token 消耗/预算使用/工具调用记录/执行结果/讨论评论/设计评审/ADR 过程/任务评论/人机对话记录）。
  2. 不获得：任务编辑/执行/取消权、Agent 控制权、预算调整权、讨论评论编辑删除参与权、正式认知确认权。
  3. 传播单层不递归：不得经只读 Project 继续继承其他 Product 成员资格。
  4. 权限并集：Product 原有权限与只读权限取并集，不相互覆盖。
- **边界保留**：PC-P 正式认知内容的读取不因普通成员资格自动开放（仍归 P4-03 DR-08 消费授权裁决）；AI 面不因人类只读获得任何新读取面。
- **影响的其他 DR**：DR-01、DR-04；P4-03 阶段 3 DR（铁律 2 吸收）。

## DR-05 — 双域独立敏感区与环境×敏感等级两维度

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **裁决问题**：敏感区的领域归属与两维度模型。
- **上游冻结约束**：P3-11 冻结令第 1/11/12 项（双域权威、共享基础设施≠共享权威、跨域引用≠授权）——敏感区按 Product/Project 分立即继承该边界。
- **决策方向〔CONFIRMED〕**：Product / Project 各自独立敏感区（资源、授权、审计、索引、Index Generator 五要素独立）；不合并为 Tenant 全局敏感知识库；环境分类（Production/Staging/Testing/Development）与敏感等级（Sensitive/Non-sensitive）为两个独立维度；环境默认表成立但环境不能决定最终敏感等级（Testing/Development 含真实凭据仍须标敏感；Production 默认敏感且不允许自动降低）；Owner 可标记/解除（解除须二次确认+审计）；Tenant Admin 管授权机制不代行业务敏感性判断；普通 Modify 不含敏感等级调整权；降级必须重查访问范围。
- **OPEN**：敏感等级元数据的存储归属与字段契约（实施任务包）。

## DR-06 — 敏感资源独立存储与受控资源入口

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **决策方向〔CONFIRMED〕**：敏感正文独立存储；普通文档仅引用稳定资源 ID；系统生成受控入口；点击时（访问时）重查该人类用户 Read 权限；未授权者仅见「受限敏感资源」通用名称，不见文件名/服务器名/路径/描述/摘要/敏感元数据；全部入口（UI/搜索/API/下载/导出）强制检查；敏感区不进普通 KB 全文索引与 PageIndex 索引；以独立存储+访问时授权为核心，不以敏感属性传播为主要安全机制；不提供把敏感正文写入普通文档的系统通道。
- **上游冻结约束**：P3-11 第 12 项（跨域引用不构成授权——受控入口的访问时检查即该原则的资源级执行）；kb 检索基线 D-4 密级过滤钩子（实施期对接）。
- **OPEN**：敏感资源引用 ID 的契约形态（与 P3-D04 DomainRef 现行契约对齐，不替其裁决）。

## DR-07 — 人类敏感区三权限（Read / Modify / Use）

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **决策方向〔CONFIRMED〕**：Read/Modify/Use 三权限独立授予、可组合；Use≠Read；Modify 不自动含 Read、不自动含 Use；读取/修改/使用/授权/撤销全程审计；授权独立于普通成员资格（普通成员资格不自动获得敏感区访问权）；Tenant Admin 管授权机制但不自动获得明文读取权；来源失效立即撤销、实时重查。
- **边界声明**：不得把 Use 解释为普通 Agent 可自动使用敏感信息；Agent 受控 Use 归 OPEN（O4）另行裁决。
- **OPEN**：Use 的未来支撑机制与适用任务类别（O4）；敏感区授权人员的管理界面与审批形态。

## DR-08 — 普通 Agent 敏感区访问边界

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决；本轮核心架构决定）**

- **决策方向〔CONFIRMED〕**：敏感区正文不对任何普通 Agent 开放；Agent 不读取/不入上下文/不展示/不增删改（仅可建议）；不得复制正文到普通文档/任务记录/Agent Memory/普通 KB/对话输出；不得经委派、共享记忆、搜索摘要、其他 Agent 或上下文传递绕过；人类点击受控入口由系统独立检查该人类 Read 权限；不为普通 Agent 配置敏感正文 Read 权限；Agent 可知敏感区存在、可搜受控目录元数据；搜索不返回总数/未授权数量/分布统计；无匹配不得暴露隐藏资源存在（防枚举）；Agent 只能提供系统生成的受控入口。

## DR-10 — Index Generator 隔离与自动发布契约

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；待人工裁决）**

- **决策方向〔CONFIRMED〕**：
  - 隔离：Index Generator 为独立受控机制；可在受控条件下读敏感正文用于生成脱敏目录；普通 Agent 不可调用它获取正文；其不得把原始正文写入普通 Chat/Agent Memory/普通 KB；输出必经独立脱敏检查；读取能力不得赋予普通 Agent。
  - 发布：自动生成/更新后直接发布（领域 Owner 事后检查，无需事先审批）；**脱敏检查为发布前强制步骤**（高风险信息检测：密钥/密码/服务器地址/Token/连接字符串等）；检查失败阻止发布、保留上一份有效索引、产生安全告警；不得因自动发布取消脱敏检查。
- **OPEN**：运行身份、隔离机制、基础设施实现（O5）。

## DR-11 — 索引版本管理与更新触发

**Status: PROPOSED（含〔CONFIRMED 2026-11-19〕方向；周期 OPEN）**

- **决策方向〔CONFIRMED〕**：
  - 版本（方案 B）：每敏感区仅保留一份当前有效 `索引.md`；新版通过检查后直接覆盖；无历史查看、无变更历史、无回滚；失败保留上一份有效索引。边界澄清：不保留索引历史≠敏感资源正文不需要按领域规则管理版本。
  - 触发（方案 C）：事件触发（资源新增/修改/删除及其他影响索引的变化）+ 定期完整扫描（核对资源与索引一致性、修复遗漏）；两机制同走 §DR-10 发布规则。
  - 并发要求：候选索引携带单调序，旧候选不得覆盖较新有效索引；必须幂等；必须处理资源删除；失败候选不得发布为当前有效索引。
- **OPEN**：定期扫描具体周期（O1，待配置/待裁决，禁止写死）；并发/幂等/失败恢复的具体实现契约（O6）。
