# AI-PM 腾讯文档发布 · 产品需求文档（PRD）V1.0

> **一句话**：用户在 AI-PM 里写好文档，点一下用自己的腾讯文档账号发布一份在线文档，拿到链接发给客户协作查看。
>
> **本质判断**：这不是「导出」，是**数据外发**。文档一旦发出去就离开本系统管控范围，因此设计重心不是「发得方便」，而是**授权清晰、权限可控、随时可收回、全程可追溯**。

## 一、可行性核实结论（2026-10-31 查证）

| 项 | 结论 | 依据 |
|---|---|---|
| 个人开发者能否接入 | ✅ **能** | 开放平台支持选「个人开发者」主体，实名认证（姓名/身份证/手机），审核 1–3 工作日 |
| 授权方式 | OAuth 2.0 授权码模式 | 用户跳转腾讯文档授权页 → 回调带 `code` → 后台换 token |
| Token 生命周期 | Access Token **30 天**，Refresh Token **1 年** | 比常见 2 小时 token 友好，但 Refresh Token 等于长期凭证，必须加密存储 |
| 免费额度 | 20,000 次调用 | 对内部工具够用 |
| 创建文档 | ✅ 新建在线文档 | `scope.file.creatable` + `scope.doc.editable` |
| 导入文件 | ✅ 支持 xlsx/docx 等导入为在线文档 | 工期核算导出的 Excel 可直接变成在线表格 |
| 设置权限 | ✅ `private` / `members` / `publicRead` / `publicWrite` | 文档权限接口 |
| 添加协作成员 | ✅ `add_collaborators` | 指定人共享 |
| **前置门槛 1** | ⚠️ **回调地址必须 HTTPS** | 本地开发需内网穿透（ngrok / frp），不能用 `http://localhost` |
| **前置门槛 2** | ⚠️ 应用需先注册审核 | 1–3 工作日，**本功能排期前必须先启动注册**，否则代码写好也联调不了 |
| **前置门槛 3** | ⚠️ 用户须实名认证 | 每位要发布的用户都需完成开放平台实名（与企业 OA 账号无关） |

> 接口路径与 scope 名以开放平台文档为准，实现时逐项核对，本文不硬编码未查证的端点。

## 二、背景与目标

### 2.1 背景

AI-PM 已经把项目认知沉淀为文档（知识空间的 Markdown 正文、工期核算的 Excel）。但交付给客户时仍要：导出文件 → 打开腾讯文档 → 手动新建 → 复制粘贴 → 排版重来 → 再设权限分享。一份文档 10 分钟，且每次改版都要重来一遍，客户手里的版本和系统里的版本必然错位。

### 2.2 目标

| 编号 | 目标 | 口径 | 目标值 |
|---|---|---|---|
| G-01 | 缩短发布耗时 | 从点按钮到拿到可分享链接 | ≤ 10 秒 |
| G-02 | 消除版本错位 | 每次发布有内容哈希快照，可查「客户看到的是哪一版」 | 100% 发布带快照 |
| G-03 | 外发可收回 | 已发布文档支持一键改回仅自己可见 | 100% 可收回 |
| G-04 | 外发全程可追溯 | 谁、何时、把哪份、发给谁、什么权限，全留痕 | 100% |

### 2.3 三条设计原则（本功能的骨架）

| # | 原则 | 含义 |
|---|---|---|
| P1 | **单向推送，不做双向同步** | AI-PM 是权威源，腾讯文档只是给客户看的投影。腾讯文档上的改动不回写系统，避免权威源混乱与冲突合并 |
| P2 | **默认最严权限** | 新建即 `private`（仅自己可见），要共享必须显式选档位；`publicRead`（链接可看）需二次确认并写风险提示 |
| P3 | **发布即快照** | 每次发布记录内容哈希与版本号，改文档后重新发布生成新记录，历史记录不覆盖 |

## 三、名词与术语

| 术语 | 定义 |
|---|---|
| 绑定（Binding） | 一个 AI-PM 用户与一个腾讯文档账号的 OAuth 授权关系 |
| 发布（Publish） | 把 AI-PM 内的一份内容推送到腾讯文档，生成一份在线文档并记录链接 |
| 源对象（Source） | 被发布的内容，如知识文档、工期核算单、需求条目 |
| 权限档位 | `private` 仅自己 / `members` 指定人 / `public_read` 获得链接的人可查看 |
| 收回（Revoke） | 把已发布文档的权限改回 `private`，使外部链接失效 |
| 权限漂移 | 用户在腾讯文档网页端自行改了权限，与本系统记录不一致 |

## 四、需求范围

### 4.1 包含

- 腾讯文档账号 OAuth 绑定 / 解绑 / 状态查看
- 三类源对象发布：知识文档（Markdown）、工期核算单（Excel 导入）、需求条目（Markdown）
- 权限三档设置 + 协作成员添加
- 发布记录与链接回写（在源对象上可见「已发布」状态与链接）
- 一键收回（改回 private）
- 重新发布（内容更新后推新版本，可选择「更新原文档」或「新建副本」）
- 发布审计

### 4.2 不包含

1. **不做双向同步**——腾讯文档的编辑不回写 AI-PM。
2. **不做腾讯文档内容读取**（不把腾讯文档当知识源导入）。
3. **不做企业统一账号代发**——V1 是「用户自己的账号」，组织级账号池是 V2 议题。
4. **不做 PPT / 思维导图 / 收集表**——V1 只做文档（doc）与表格（sheet）。
5. **不做客户侧访问统计**（谁看了、看了多久）——腾讯文档侧不提供，也无法伪造。

## 五、方案对比与选型

### 5.1 发布形态选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 新建在线文档（doc） | 调 API 创建 doc，正文用 Markdown/HTML 写入 | 客户看到的是原生腾讯文档，可评论可协作 | 复杂排版（表格、公式）保真度需实测 | ✅ **主方案** |
| B. 导入文件（xlsx/docx） | 先生成文件再导入，转成在线文档 | 排版保真度高，工期 Excel 天然适配 | 多一步转换，导入是异步任务需轮询 | ✅ **工期核算走这条** |
| C. 只生成链接让用户手动上传 | 系统只给文件 | 零集成成本 | 没解决任何痛点 | 否决 |

### 5.2 权限默认档位选型

| 方案 | 默认 | 风险 | 结论 |
|---|---|---|---|
| 默认 `publicRead`（链接可看） | 方便分享 | 链接一旦流出等于公开，客户资料裸奔 | ❌ 否决 |
| 默认 `private`（仅自己） | 最严 | 用户要多点一步 | ✅ **采用**。分享是显式动作，不该是默认结果 |
| 默认 `members`（指定人） | 折中 | 每次都要填手机号/邮箱，摩擦大 | 备选 |

### 5.3 重新发布策略

| 方案 | 行为 | 问题 |
|---|---|---|
| 每次都新建 | 简单 | 腾讯文档允许同名，客户会收到一堆同名文件，分不清哪版是最新 |
| **更新原文档**（推荐） | 复用同一 fileID 覆盖内容，链接不变 | 客户手里的旧链接自动看到新版，**这是优点也是风险**——客户可能已经基于旧版做了决策 |
| 混合 | 默认更新原文档，提供「另存为新副本」选项 | 兼顾 |

> **裁决建议**：默认「更新原文档，链接不变」，但更新时记录版本号并在文档首行写入「版本 v2 · 更新于 2026-11-05」。理由：客户只需要一个链接，多链接是灾难。风险由版本标注化解。

## 六、用户角色与场景

### 6.1 角色

| 角色 | 动作 | 前置 |
|---|---|---|
| 项目负责人 | 绑定账号、发布文档、设权限、收回 | 完成开放平台实名 + 应用审核通过 |
| 项目成员 | 查看发布记录与链接 | 无需绑定 |
| 客户 | 通过链接查看（可在腾讯文档内评论） | 无 AI-PM 账号 |

### 6.2 核心场景

**场景 1：首次绑定**
1. 设置 → 集成 → 腾讯文档卡片 → 点「绑定账号」
2. 跳转腾讯文档授权页，扫码/登录，同意授权
3. 回调回 AI-PM，显示「已绑定：昵称，授权有效期至 2026-11-30」
4. 若 Refresh Token 也过期 → 卡片显示「授权已失效，请重新绑定」

**场景 2：发布知识文档给客户**
1. 项目认知中心打开某份 PRD
2. 点「发送到腾讯文档」
3. 弹窗：标题（默认取文档标题，可改）、权限档位（默认 private）、协作成员（可空）
4. 点确认 → 10 秒内返回在线文档链接
5. 页面显示「已发布 · 私密 · 复制链接」，源文档上出现「已发布」标记
6. 用户改权限为「指定人」，填客户手机号 → 客户收到腾讯文档的协作邀请

**场景 3：工期核算 Excel 发布**
1. 工期核算页点「发送到腾讯文档」
2. 系统先导出 xlsx（复用 FR-07）→ 导入腾讯文档 → 转成在线表格
3. 返回链接，权限流程同上

**场景 4：收回链接**
1. 发布记录列表 → 找到那条 → 点「收回」
2. 二次确认：「收回后客户将无法通过原链接查看，确认？」
3. 权限改回 private，状态标「已收回」，记录收回时间与操作人

**场景 5：内容更新后重新发布**
1. 文档改了内容 → 再次点发布
2. 系统检测到该源对象已有发布记录 → 提示「将更新原文档（链接不变），当前 v1 → v2」
3. 确认后覆盖内容，链接不变，版本号 +1

### 6.3 异常流程

| 场景 | 期望行为 |
|---|---|
| 未绑定账号就点发布 | 拦截，引导先去绑定 |
| 授权已过期 | 提示重新授权，不丢当前文档上下文，授权后继续原操作 |
| 腾讯 API 限流（429） | 提示「稍后重试」，自动重试 2 次（指数退避） |
| 导入异步超时 | 显示「转换中」，可稍后在发布记录里查看结果 |
| 文档内容为空 | 拦截发布 |
| 权限漂移（网页端被改） | 发布记录标黄「权限可能已变更」，提供「重新校准」按钮 |
| 解绑时存在已发布文档 | 提示「已发布的 3 份文档仍保留在你的腾讯文档账号下，解绑后无法从本系统管理」 |

## 七、功能需求

### FR-01 账号绑定

| 项 | 内容 |
|---|---|
| 描述 | 用户通过 OAuth 绑定自己的腾讯文档账号 |
| 规则 | ① 授权 URL 带 `state`（随机串，10 分钟有效，防 CSRF）；② 回调校验 `state` 后换 token；③ Access Token 与 Refresh Token **AES-256 加密存储**，禁止明文落库、禁止出现在日志与接口响应；④ 一人一绑定，重复绑定时覆盖旧 token；⑤ 绑定状态展示：昵称、头像、Access Token 到期时间 |
| 验收 | **Given** 未绑定用户，**When** 点绑定并完成授权，**Then** 卡片显示「已绑定 + 昵称 + 到期日」，库内 token 字段为密文 |
| 验收 | **Given** 伪造 `state` 的回调，**When** 请求，**Then** 拒绝并记审计 |
| 验收 | **Given** 查库，**Then** 任何表都不存在明文 token |

### FR-02 解绑

| 项 | 内容 |
|---|---|
| 描述 | 解除绑定，清除本地 token |
| 规则 | ① 二次确认；② 已发布文档在腾讯文档侧不受影响（所有权在用户账号），但本系统失去管理能力；③ 解绑后发布记录保留，仅标「已解绑，不可操作」 |
| 验收 | **Given** 有 3 条已发布记录，**When** 解绑，**Then** 提示「3 份文档仍在你账号下」，解绑后记录只读 |

### FR-03 发布知识文档

| 项 | 内容 |
|---|---|
| 描述 | 把知识空间的一份 Markdown 文档发布为腾讯在线文档 |
| 规则 | ① 标题默认取文档标题，可改，≤ 100 字；② 正文来自知识仓库当前 `published` revision；③ 发布前校验内容非空；④ 记录源对象 id + revision + `content_hash`；⑤ 创建到用户腾讯文档的指定目录（默认根目录，可配）；⑥ 返回 `file_id` + `url` |
| 验收 | **Given** 一份 3000 字 Markdown，**When** 发布，**Then** 10s 内返回可访问链接，腾讯文档内标题与正文与源一致 |
| 验收 | **Given** 发布成功，**When** 查看源文档页，**Then** 显示「已发布」标记与链接 |

### FR-04 发布工期核算单

| 项 | 内容 |
|---|---|
| 描述 | 把工期核算单导出为 xlsx 后导入腾讯文档，转成在线表格 |
| 规则 | ① 复用工期核算 FR-07 的导出逻辑，先落临时文件；② 走「导入」接口，异步轮询进度（超时 60s）；③ 转换成功后删除临时文件；④ 表格保留单价空列与公式 |
| 验收 | **Given** 一份 40 行的工期核算单，**When** 发布，**Then** 得到在线表格，公式可用、单价列仍为空 |
| 验收 | **Given** 导入失败，**When** 轮询超时，**Then** 发布记录标失败并给出原因，不产生僵尸记录 |

### FR-05 权限设置与协作成员

| 项 | 内容 |
|---|---|
| 描述 | 发布时/发布后设置文档权限 |
| 规则 | ① 三档：`private`（默认）/ `members`（指定人）/ `public_read`（链接可看）；② 选 `public_read` 必须勾选「我已知悉：获得链接的任何人都能查看此文档」；③ `members` 需填至少一个手机号或邮箱，支持多个；④ 发布后可单独改权限；⑤ 权限变更记审计 |
| 验收 | **Given** 选「链接可看」未勾确认框，**When** 提交，**Then** 阻断 |
| 验收 | **Given** 权限从 private 改为 members 并填客户手机号，**When** 保存，**Then** 腾讯文档侧协作成员列表含该号码 |

### FR-06 发布记录与链接回写

| 项 | 内容 |
|---|---|
| 描述 | 集中查看所有发布记录，源对象上可见发布状态 |
| 规则 | ① 列表字段：标题、源对象、版本、权限、状态（成功/转换中/失败/已收回）、发布人、发布时间、链接；② 支持按项目、状态筛选；③ 源对象详情页显示最近一次发布状态与链接；④ 链接一键复制 |
| 验收 | **Given** 同一文档发布 3 次，**When** 看记录，**Then** 3 条记录按时间倒序，最新一条标「当前」 |

### FR-07 收回

| 项 | 内容 |
|---|---|
| 描述 | 把已发布文档权限改回 `private` |
| 规则 | ① 二次确认，文案说明「客户将无法通过原链接查看」；② 调腾讯 API 改权限；③ 状态转 `revoked`，记录时间与操作人；④ 收回失败（API 报错）时提示手动处理并给出文档链接 |
| 验收 | **Given** 一条 `members` 权限的发布记录，**When** 收回，**Then** 状态 `revoked`，客户侧访问被拒 |

### FR-08 重新发布与版本

| 项 | 内容 |
|---|---|
| 描述 | 源内容更新后再次发布 |
| 规则 | ① 检测已有发布记录时提示「更新原文档（链接不变）」；② 提供「另存为新文档」选项；③ 更新时版本号 +1，并在文档正文首行写入「版本 vN · 更新于 {日期}」；④ 内容哈希未变时提示「内容无变化，是否仍要发布」 |
| 验收 | **Given** 已发布 v1，**When** 改内容再发布并选更新，**Then** 链接不变，文档首行为「版本 v2」 |

### FR-09 权限校准

| 项 | 内容 |
|---|---|
| 描述 | 检测并修正权限漂移 |
| 规则 | ① 发布记录列表支持「刷新权限」（查腾讯 API 实际权限）；② 实际权限与记录不一致时标黄「权限已变更」；③ 提供「以系统为准同步」按钮，把腾讯侧改回记录值 |
| 验收 | **Given** 用户在腾讯文档网页端把 private 改成 publicRead，**When** 点刷新权限，**Then** 记录标黄并显示实际权限 |

### FR-10 审计

| 项 | 内容 |
|---|---|
| 描述 | 全部外发动作留痕 |
| 规则 | 记录：bind / unbind / publish / permission.change / revoke / republish。字段含操作人、项目、源对象、目标文档、权限、结果。复用 `governance.audit_log` 与 SSE 审计流 |
| 验收 | **Given** 一次发布 + 一次改权限 + 一次收回，**When** 查审计，**Then** 三条记录齐备 |

| 类别 | 要求 |
|---|---|

## 九、业务流程与状态流转

### 9.1 发布流程

```
点「发送到腾讯文档」
      ↓
已绑定？ ──否──→ 引导绑定（授权 → 回调 → 存加密 token）→ 回到原流程
      ↓ 是
选择源对象类型
  ├─ 知识文档 → 取当前 published revision → 新建 doc
  ├─ 工期核算 → 导出 xlsx → 导入 → 轮询 → 转在线表格
  └─ 需求条目 → 取最新 revision → 新建 doc
      ↓
设置标题 / 权限档位（默认 private）/ 协作成员
      ↓
调腾讯 API 创建 → 拿 file_id + url
      ↓
若权限非 private → 调权限接口设置
      ↓
落发布记录（含 content_hash、版本、权限、快照）
      ↓
回写链接到源对象 → 记审计
      ↓
返回链接（可复制）
```

### 9.2 发布记录状态机

| 状态 | 含义 | 可转至 | 触发 |
|---|---|---|---|
| `publishing` | 创建中 / 导入中 | `published` / `failed` | API 返回 |
| `published` | 成功，可访问 | `revoked` / `updated` / `failed` | 收回 / 重新发布 / 权限操作失败 |
| `updated` | 已更新（同一链接，版本 +1） | `revoked` | 收回 |
| `revoked` | 已收回（private） | `published`（重新开放） | 重新设权限 |
| `failed` | 失败 | `publishing`（重试） | 重试 |

> `revoked` 可回到 `published`——与工期核算的「导出即冻结」不同，外发权限本质是可逆的，这是本功能与导出功能的关键差异。

### 10.3 指标口径

| 指标 | 计算式 | 用途 |
|---|---|---|

| 公开链接占比 | public_read 发布数 ÷ 总发布数 | 安全指标，应长期接近 0 |

## 十一、权限与安全

| 操作 | project_owner | 项目成员 | 观察者 | 备注 |
|---|---|---|---|---|
| 绑定/解绑自己的账号 | ✅ | ✅ | ✅ | 绑定是个人行为，与项目权限无关 |
| 发布文档 | ✅ | ❌ | ❌ | 外发是高危动作，需 owner 级 |
| 查看发布记录与链接 | ✅ | ✅ | ✅ | 链接可见即可转发，故要求项目内可见 |
| 改权限 / 收回 | ✅ | ❌ | ❌ | 同发布 |
| 查看他人绑定状态 | ❌ | ❌ | ❌ | 只可见自己 |

**权限码**：`PM_DOCS_BIND` / `PM_DOCS_PUBLISH` / `PM_DOCS_REVOKE`。

### 11.1 安全硬要求

1. **Token 加密**：AES-256-GCM，密钥来自环境变量 `PM_DOCS_TOKEN_KEY`，不入库、不入仓、不入日志。
2. **日志脱敏**：任何日志、错误详情、接口响应中，token 与 open_id 一律脱敏（只留前后 4 位）。
3. **回调安全**：`state` 一次性、10 分钟过期；回调仅接受 HTTPS；限流 10 次/分钟/IP。
4. **二次确认**：`public_read` 与「收回」两个动作强制二次确认。
5. **审计不可关闭**：外发相关审计为强制项，不随项目配置关闭。

## 十二、异常处理清单

| 编号 | 场景 | 处理 |
|---|---|---|
| E-01 | 未绑定账号 | 拦截并引导绑定，不丢当前上下文 |
| E-02 | Access Token 过期 | 用 Refresh Token 自动续期，用户无感 |
| E-03 | Refresh Token 也过期（>1 年未用） | 提示重新绑定，标记 `expired` |
| E-04 | 腾讯 API 429 限流 | 指数退避重试 2 次，仍失败则提示稍后 |
| E-05 | 腾讯 API 5xx | 记录失败，提供重试按钮，不产生半截记录 |
| E-06 | 导入转换超时（>60s） | 标「转换中」，允许稍后刷新；超 10 分钟判失败 |
| E-07 | 内容为空 | 阻断发布 |
| E-08 | 标题超长（>100 字） | 截断并提示 |
| E-09 | `members` 档位未填任何成员 | 阻断提交 |
| E-10 | 协作成员手机号/邮箱格式非法 | 阻断并定位 |
| E-11 | 源对象已删除 | 发布记录保留，标「源已删除」，链接仍可访问（腾讯侧独立） |
| E-12 | 解绑时存在已发布文档 | 明确告知文档仍在用户账号下，解绑后不可管理 |
| E-13 | 同一内容重复发布 | 提示「内容未变化」，允许强制发布 |
| E-14 | 收回失败（API 拒绝） | 提示手动到腾讯文档改权限，给出直达链接 |
| E-15 | 用户在腾讯侧删除文档 | 刷新权限时返回 404，记录标「已达不存」，提示重新发布 |
| E-16 | 并发发布同一文档 | 加锁（source_kind + source_id），第二次提示「正在发布中」 |
