# 8. 产品认知建立方式

## 8.1 两种建立路径

**正式沿用既有裁决：从零建立与从现有资料提取并行。**

### 路径 A：从零建立

适用于新产品或缺少现有资料的项目。

- 团队与 AI 逐步定义 Product Vision；
- 建立业务能力和功能模块；
- 定义角色、场景、流程、业务对象及规则；
- 形成认知草稿；
- 按审批矩阵逐步确认。

### 路径 B：从现有资料提取

适用于已有产品。

输入可以包括：

- 需求文档；
- 会议记录；
- 设计稿；
- 产品说明；
- 用户反馈；
- 已审核知识；
- 历史决策资料。

KB 负责资料解析与知识提取。

PC 负责判断其对产品认知的意义，并形成认知草稿或变更提议。

## 8.2 来源与可信度

提取内容必须保留：

- 原始资料身份；
- 资料版本；
- 来源位置或内容定位；
- 提取时间；
- 提取方式；
- 可信度；
- 审核状态；
- 对应的认知对象。

AI 提取内容不能自动成为当前有效产品事实。

## 8.3 原始资料与代码边界

PC 的资料输入以产品文档和知识为主。

用户已明确：普通代码文件不进入 Product Cognition 文档分析流程。

文档类资料由 Knowledge Base 感知、解析和提取。

如果 Git Commit 只涉及普通代码变化，不触发 PC 文档知识提取流程。

如果 Git Commit 涉及 Markdown、PDF 等知识文档，则由 KB 根据实际接入机制感知和处理，再由 PC 分析认知影响。

# 9. Knowledge Base 浅层记忆与深层资料

## 9.1 L1 Shallow Memory

浅层记忆是经过人工审核、适合长期使用的结构化知识。

**既有正式裁决：所有浅层记忆内容变化都必须人工审核。**

适用变化：

- 新增；
- 修改；
- 删除；
- 合并；
- 改变原有含义。

AI 可以生成候选更新，但不能直接修改正式 L1 内容。

## 9.2 L2 Deep Memory

深层资料包括：

- 原始文件；
- 完整解析内容；
- 详细历史资料；
- 完整讨论和证据。

AI 可以自动解析、整理、分类和建立索引，但不得覆盖原始文件。

## 9.3 浅层记忆版本化

人工审核通过后：

1. 每条浅层记忆保持稳定身份。
2. 每次正式变更生成新版本。
3. 旧版本保留只读历史。
4. 删除使用逻辑失效或退役，不物理删除历史记录。
5. 合并保留源条目，并建立合并或取代关系。
6. 每次变更保留来源、审核人、审核时间、理由和前后版本。
7. 候选版本审核前不影响当前有效记忆。

## 9.4 L1 与 L2 检索

- L1 默认用于日常认知检索。
- L2 在需要还原历史、核实证据或分析争议时深入检索。
- L1 没有结果，不代表历史上从未讨论。
- L2 发现的新证据可以补充 L1 候选内容。
- 任何 L1 正式变化仍须人工审核。

## 9.5 多项目资料关联

一份原始资料可以关联多个项目。

如果资料关联项目 A 和项目 B：

- 两个项目的有效成员均可阅读完整原始资料；
- 不做片段隔离；
- 每个项目分别生成自己的知识提取；
- 每个项目分别关联自己的 Product Cognition。

资料访问权限动态继承项目成员权限：

- 用户是任一关联项目的有效成员且具有读取权限，即可读取完整资料；
- 失去某项目权限但仍属于另一关联项目，仍可读取；
- 失去所有关联项目资格后，不可读取；
- 上传者不享有永久访问特权。
