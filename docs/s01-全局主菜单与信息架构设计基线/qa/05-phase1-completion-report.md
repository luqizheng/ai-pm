## 4. Phase 2 建议（测试用例设计，按第二轮审查要求更新）

1. **测试策略先行**：Phase 2 不机械地按 92 条需求产生用例，先按风险建立测试策略（P0-1 隔离 → P0-2 身份边界 → P0-3 Native 独立可用 → P0-4 归档撤权 → P0-5 Finding 生命周期 → P0-6 仓库范围 → P0-7 基线确认 → P1 正常流程 → P2/P3 UI 与待裁决），策略表见 `04-s01-test-coverage-baseline.md` §9。
2. **用例映射**：92 条 RTM → 测试用例，P0 29 条优先；**每个 Test Case 必须反向追溯一个或多个 Requirement ID** + 既有验收编号（I1/I2/I3/I4/I5/I6-B/S01-A/C 段），避免与既有自动化重复。
3. **安全测试场景族**：正向、反向、越权、并发、重放，不只验证正常流程。
4. **九大端到端场景**（任务书 §4）按 M1→M2→M4→M3→M6→M7 依赖序设计；Scenario 07（项目隔离）/08（归档）承载 P0 主力。
5. **双入口一致性**（REST vs MCP）作为独立用例族（S01-SEC-067），沿用 S02-02 的独立实例+独立库方法（与演示栈零污染）。
6. **运行时首证项**：跨项目写路径（S01-SEC-010/063）、并发终态（S01-DATA-068）、审计原子性（S01-DATA-066）、归档注入失败回滚（S01-FR-071 的 I1-004/005）、DATA-020 六步一致性——须包含 DB 侧复核，不仅看响应码。
7. **环境**：沿用独立核验实例模式（参考 `docs/s02-02-requirement-runtime-verification-v1.md`）；测试项目/账号独立，结束后清理。
8. **场景合并**：BR-011↔ADR-041 共用一套核心场景；BR-044↔BR-047 分别测试、不互相替代。
