  长函数拆分（claim_core 410 行、propose_import 270 行）留作独立任务。
- 方式：同 crate 子目录 + mod.rs 重导出，对外路径不变，crate 依赖图不变。

### 结果
各文件 → 5-6 个子模块（mod / 主流程 / 子职责）。拆分后最大单文件是
command_executor/executor.rs 1014 行（impl PgCommandExecutor 一个块，不拆函数体
时不减少）、run_dispatch/claim.rs 606 行、project_import/lifecycle.rs 451 行。

### 技术点（踩过的坑，下次直接避开）
1. **可见性**：拆出的自由函数需从 `fn` 提升为 `pub(crate) fn`（跨子模块调用），
   否则报 E0425。用正则批量改 `^(async )?fn` / `struct` / `enum` / `const`。
2. **use 处理**：不要复制原文件的多行 use 块到子文件（`use pm_domain::{ ... };`
   的续行极易被脚本合并成一行）。改为：mod.rs 保留 header 并把 `use` 提升为
   `pub(crate) use`，子文件只写 `use super::*;`。由此 mod.rs 需要
   `#![allow(unused_imports)]`（这些 import 是为子模块共享而存在）。
3. **PowerShell 写文件**：`Set-Content -Value (数组)` 的换行行为不可靠，
   用 `[System.IO.File]::WriteAllLines(path, [string[]]arr, UTF8Encoding(false))`；
   读用 `ReadAllLines`。中文文件必须显式 UTF8，否则乱码。
4. **脚本路径**：`Split-Path  -Leaf` + `Join-Path (Split-Path  -Parent)`
   在相对路径下易把目录生成到 crate 根（少 `src/`）。用 `Resolve-Path` 取绝对路径。
5. 切分边界以「完整 top-level item」为单位，向前回溯 `///` / `//!` / `#[` 注释块。

## 测试加速：template1 预建（已落地）

### 机制
#[sqlx::test] 每用例都裸 `CREATE DATABASE`，Postgres 默认模板写死是 `template1`
（**不可配置**）。所以只要把 migrations 预跑进 `template1`（含 `_sqlx_migrations`
记账行），建库就退化成文件拷贝、sqlx 查到全部 applied 后跳过所有 DDL。
**零测试代码改动**（300 个用例原样）。

### 关键裁定
用户原提方案是「建 `aipm_test_tpl` + 每用例显式 `TEMPLATE` + 自写 fixture」。
技术上与现有方案**互斥**：显式 TEMPLATE 必须放弃 `#[sqlx::test]` 宏，要把 49 个
文件 / 300 个用例全部改签名，而实测收益只多 ~0.02s/用例。用户裁定保留 template1 方案。

### 实测（本机 5433）
- 单用例 core_schema：2.5s → **0.25s**
- 6 用例并行 migration_0015：**0.53s**
- 全量 `cargo test --workspace`：**157s**（67 ok / 420 passed / 0 failed）

### 工具
`crates/pm-infrastructure/examples/seed_test_template.rs`：迁移指纹（version+checksum）
自愈、`pg_advisory_lock` 互斥、非 localhost 拒绝执行、`AIPM_TEST_SKIP_TEMPLATE=1`
可跳过。`scripts/cargo-test.sh` 跑测试前调用，失败只告警（回退慢路径）。

### 边界
template1 被写入业务 schema 后，该实例上**所有** `CREATE DATABASE` 都会带上这些表。
仅限本地 dev/test 实例；生产库不得照搬（README 与 compose 已写明）。

### 顺手清理
dev 实例删掉 5 个探测库（perf_clone / perf_m / perf_probe / perf_probe2 / probe），
只留 `aipm` 与 `postgres`。无 `_sqlx_test_*` 残留（测试都正常清理）。

### flake 结论
偶发 `database "_sqlx_test_..." does not exist`：并发建库时 `CREATE DATABASE` 的
全局锁竞争（同一时刻我并行跑了多个 cargo test 进程最易触发）。模板克隆缩短了持锁
时间，概率已下降。排查时注意「不要并行跑多个 cargo test」。
