## 前端工程坑（本次踩到，务必记住）

1. **i18n 命名空间规则**：`locales/<locale>/<ns>/<file>.yaml` 的**顶层键必须等于文件名末段**（`<file>`），否则会双重嵌套导致 key 解析不到。如 `s01/initialization.yaml` 顶层写 `initialization:`，不是 `s01:`。
2. **YAML 裸值不能以 `{` 开头**（如 `{count} 份提案待审`）→ 需加引号；同层重复 key（如 `role` 同时作标量与映射）会导致解析报错。
3. **reka-ui `Select` 不接受空字符串作为 item value** → 用哨兵值（如 `__all__` / `__none__`）。同理 `Select` 的 `TabsTrigger` 在 happy-dom 下监听 **mousedown** 而非 click，测试须 `trigger("mousedown")`。
4. **i18n 是全局单例**：`i18n-helpers.test.ts` 会 `setLocale("en")` 并持久化到 localStorage，全量并行时其他测试会读到英文 → 新测试在 mount 前必须 `setLocale("zh-CN")`。
5. **沙箱 TEMP 限制**：跑 vitest 前须 `export TEMP="$(pwd)/.testtmp" TMP="$(pwd)/.testtmp"`，否则报 `EPERM ... open ... Temp`（已知的 agent 沙箱噪声）。
6. **Windows heredoc 陷阱**：bash heredoc 里的 `\n` 会被 Python 当作字面两字符，批量改文件时应显式 `chr(10)` 或用 `.replace()`。
7. **`check-vitest-coverage.js` 门禁脚本在 `scripts/` 下并不存在**（`frontend/AGENTS.md` 提到但未落地）——非本次引入。
