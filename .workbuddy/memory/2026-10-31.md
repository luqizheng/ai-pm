# 2026-10-31 · ai-pm 文档通读（初建立项目认知）

## 项目定位
每项目专属 AI-PM（Rust + PostgreSQL + Vue3 前端同仓）。信任模型 V2「AI 主导」：非红线默认自动执行，人类为监督者（否决/刹车/政策制定），红线动作事前确认。

## 架构要点（已读文档）
- 七条架构原则：一项目一逻辑 AI-PM、AI 是主角、统一命令通道、先保存再分析、权威状态可回滚、红线事前确认、全链路可追溯。
- 三类数据：原始事实 / AI 分析 / 权威业务状态（权威 = 系统正式承认的最新版本，不因写入者是 AI 打折）。
- 部署：模块化单体 + 独立 AI Worker（pm-api / pm-mcp / pm-worker / ai-pm-worker / postgres / RustFS）。
- 产品侧：混合式工作空间（AI 原生空间 6 入口 + 传统业务空间），`/workspace/:projectId/*`，`/focus/:objectType/:id` 为无损切换载体；附录 C/D 给出 /focus 规格与 WorkspaceSession 语义。
- 知识空间：Markdown 正文权威在 Git 仓库，PG 只存身份/路径/revision/commit/hash，PageIndex 为派生索引。

## 前端 Markdown 编辑器选型与落地（已完成，待浏览器实跑验证）
- **结论：Vditor 4.0.1**（MIT / 月更 / Lute 引擎，md 字符串即真源，wysiwyg 模式给非技术用户）。
- 排除 TipTap：官方 `@tiptap/markdown` 以 JSON 为数据源，真实语料往返实测 33 份仅 22/33 幂等 → 每次自动保存都会重写文件。排除 Milkdown+Crepe：能力好但粘贴/拖拽上传与附件节点需自写，成本 5–8 天；Vditor 的 `upload.handler` 可完全接管上传。
- **Vditor 源码实测坑（类型声明会误导）**：`upload.handler` 返回 string 会被当提示条且**不插入内容**；返回 null 才视为成功，插入必须 handler 自己调 `insertValue`。
- **Vditor 部署坑**：lute 引擎（`dist/js/lute/lute.min.js` 单文件 3.6MB）是运行时 `<script>` 动态加载，默认走 `unpkg.com`，内网不可达 → 编辑器起不来。已加 `scripts/sync-vditor-assets.js` 把 lute/content-theme/emoji 同步到 `frontend/public/vditor/`，组件侧 `cdn` 指向 `BASE_URL + /vditor`。dev/build 脚本已前置调用；`public/vditor/` 进 gitignore。
- **RustFS 约束**：S3 兼容矩阵中 POST Object 表单上传「计划支持」未实现 → 禁用一切浏览器表单直传；预签名 GET/PUT 与分片上传可用。附件统一走 `file-services`（multipart → /gw → api-gateway `/v1/file/*`），不直连 S3。
- **正文引用约定**：图片/附件一律写 `/v1/file/{id}`，**绝不写预签名地址**（会过期，存档失效）。渲染时按 id 现签现用，`hydrateFileRefs` 就地替换 DOM 不回写 md。
- 交付：`frontend/src/components/ui/markdown-editor/`（MarkdownEditor.vue / MarkdownViewer.vue / file-ref.ts / upload-handler.ts / cdn.ts / types.ts / index.ts）+ `shell/api/attachments.ts`（上传与预签名端口实现，含 15min 缓存与提前 1min 重签）+ `locales/{zh-CN,en}/markdown.yaml`。
- 门禁：37 单测绿 / vue-tsc 0 错 / prism-tokens / i18n 双门禁 / ui.contract 12 例 全过。存量 `src/workspace/**` 有 54 处 prettier CRLF 报错（非本次引入）。
- **未验证**：沙箱无法开浏览器，编辑器实跑（lute 加载、粘贴上传、样式落地）需本地 `pnpm dev` 确认。构建验证受沙箱安全删除守卫拦截（`rimraf dist`），需本地跑 `pnpm build`。
- 待定：是否需要「用户可切 markdown 源码」。Vditor 的 `mode` 构造时固定，切换须销毁重建实例（丢撤销栈与光标）。

## 15:0x 记录任务状态体系规格（V1，最重要的一篇）

- 新增 `docs/tasks/ai-pm-task-state-machine-v1.md`（约 560 行，8 节 + 2 附录）。三图归档 `docs/figures/state-machine-v1-{overview,cross-repo,policy-prototype}.png`。
- 设计理念（原文）：服务端状态机为核心 + 自动化优先 + 关键决策人工审批。AI 可自主推进执行，但不得改目标/验收规则/正式架构决策，也不能靠一句"我完成了"完成任务。
- **13 态**：Draft / Ready / Claimed / Running / Blocked / AwaitingDecision / Submitted / Reviewing / Completed / ChangesRequested / Cancelled / Failed / Superseded（图注提及，规则表无迁移边 → Q1）。关键细节：Claimed/Running/Submitted 是**业务状态**，Codex 启停崩溃重试记在 `task_runs`，故状态机里没有"重试中"。
- **三级权限**：A 级 6 项自动推进、B 级 5 项策略后自动、C 级 5 类必须人审。**审批不绑状态**（同一条 Reviewing→Completed，文档任务可自动、架构任务必须人工）→ 审批是 `(任务类型, 风险, 操作)` 三元函数。两条正交约束：审批不绑状态 + **提出者不得自批**。
- **16 条转移规则表**原文照录，两个例外：E1 Running→Submitted 不能只看 Codex 声明（须验 Commit/变更/测试/清单）；E2 Reviewing→Completed 不能只看测试绿（须验验收标准 + 审批策略）。
- **仓库级交付状态机 5 态**：Pending / Committed / Validated / Changes Requested / Merged；任务层聚合取最差态；**交付验收 ≠ 集成合并**（三仓 Validated 未合并也可完成交付验收，项目策略可要求合并才算完成）；`base_commit` 过期要重评，冲突/接口变化要求**重新验证**，禁止静默覆盖。
- 五类人工决策（目标范围变更 / 正式架构决策 / 高风险代码 / 正式知识生效 / 不可逆外部操作）。
- **策略引擎原型（图3）与一处需澄清**：三个开关全开，但架构任务「任务完成审批」仍是「默认人工验收」→ 开关表达"允许上限"而非"结果"，合成规则未明示（Q4）。五条优先级 P1–P5，其中 P2 **任务级只能收紧不能放宽**（向下取严）、P5 要求策略**版本钉住**。
- Rust 建议：domain/{task,task_state,task_transition,approval_policy,task_run,delivery_manifest} + application/{claim,submit,request_changes,accept,decide}_task|approval + infrastructure/{postgres,git,codex} + interfaces/{http,mcp}；核心思想「所有状态变化都过统一 task_transition」。伪代码原文含 7 步。
- **实测对账（关键结论）**：伪代码 7 步里事务/行锁/乐观锁/审计/回执 5 步**已有且质量好**（`update_task_status` 用 `FOR UPDATE` + `expected_revision` + 同事务写 `audit_log` + `CompensationSpec::Restore` 补偿快照 + 返回 `ExecutionReceipt`）。真正缺的只有两件：**权限判定升级为三元策略** + **证据校验与状态机规则**。策略引擎形状也对（黑名单 auto_apply + 7 条 red_lines，其中 `sign_acceptance → authorized_acceptor` 已覆盖 C3 一部分），缺任务类型维度、任务级策略、版本钉住与变更留痕。
- **迁移映射**：现有 5 值 → 新 13 值。`in_progress` 一拆二（Claimed/Running，需回填是否有活跃 Run）；`needs_info` **无对应**（Q2）；`done`→`Completed` 需检查验收证据，无证据者单列「历史遗留完成」不静默迁移。M4：新值须与前端徽标同源。
- 首版范围原文：固定状态机 + 可配置审批策略 + 不可变事件审计，不做复杂工作流引擎。Q1–Q11 已列。
